# Automatic handling of recoverable local failures

The worker now treats unavailable read-only terminal status as an observation problem. A status CLI crash, timeout, invalid response, or temporarily non-realtime recovery observation reconnects while the existing heartbeat/lease remains healthy. The worker keeps the original terminal identity and does not reserve another provider request, resubmit the PDF, or mark the effect unknown solely because a status read failed. Identity conflicts still fail closed. Lease loss, pause, cancellation, and drain prevent automatic reconnection.

New workflow executions automatically retry local export outcomes `input_invalid` and `storage_unavailable` after 5, 15, and 30 seconds. These retries run only `export_terminal_scene_prompts`, reading retained responses and writing local output. They never invoke a NotebookLM turn or scene generator. Operator pause/cancellation is checked before each retry. Persistent errors enter a queryable pause after the retry budget; invalid data is not discarded or marked successful.

Export journal observations use activity/attempt identities so a later successful retry cannot collide with an earlier failed observation. True uncertain remote effects, authentication/account failures, data/identity conflicts, and existing holds are not silently released.

A Temporal patch marker preserves already-recorded histories. The historical uploaded run's existing hold is therefore retained for its final owner-authorized recovery; the new retry policy prevents the corresponding routine false holds on future executions. Restarting the services does not authorize continuation of that run.

Regression checks cover automatic local recovery without operator resume, cancellation, bounded exhaustion, repeated journal observation, reconnecting to the same terminal without a submit command, lease-loss termination, native status crash retries, and no retries of mutating CLI commands.
