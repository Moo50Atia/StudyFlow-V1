## Ordering and task notes

Execute T001→T002, then each test/implementation pair in listed order. T003 may be authored after T001 while dependency resolution proceeds, but T004 requires T002. No other task is marked parallel: shared schema/contracts make unreviewed simultaneous edits risky. Tests must precede the implementation they govern; regressions already passing remain passing.

Critical traps: single source FK cannot represent two files; `System Ready` is not a finished Lesson; Framework/Third digests differ from legacy constants; SDK may retry internally; remote registration is not readiness; recent listing is incomplete; repeated Continue is not an ID; SQLite ignores `lockForUpdate` unless guarded by real transactional writes; Temporal activity results are history; files are not DB-transactional; shared event keys suppress later work; demo JEV does not approve scenes/teacher decisions. Details and stop conditions are in [notes](implementation-notes.md).
