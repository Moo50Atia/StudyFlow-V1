# Downstream integration and supersession

For direct cases this spec supplies original Document + approved framework + manifest → ready map → complete lesson bundle → existing original prompt versions and completion receipts. It proves these only after implementation gates pass. It does not itself supply live JEV evidence, a checked scene or teacher approval.

Existing text-only `KnowledgeSourceAdapter.query_once_by_binding` remains legacy. New source-context resolver dispatches by immutable binding mode. Qualification revision/correction may ask source-grounded research questions through the new conversation port, but must use a **separate conversation** and its own effect ledger, never the lesson protocol conversation. Verify the SDK can explicitly create an isolated conversation without defaulting to the existing chat; if not supported, this integration gate is blocked and must not send a correction in the lesson thread. Existing downstream test fixtures may simulate this capability but cannot establish live support.

The approved JEV demo waiver may continue only in the existing explicit local/demo configuration with Choice pass, Score100, Noul1 and visible waiver provenance. It never changes production policy, browser checks or teacher approval. Report a demo with waived JEV separately from a fully verified pipeline. Missing JEV credentials can block the production end-to-end gate while NotebookLM adapter tests progress independently.

Do not edit older numbered specifications during implementation to erase contradictions. Treat this document as the versioned amendment for captured direct cases. Repair actual code consumers named in tasks and prove their boundaries with connected tests; any unrelated baseline repair belongs in an explicit follow-up report, not hidden scope expansion.
