## TDD and verification discipline

- Test tasks precede corresponding new behavior. Tests must execute real controller/signature/service/DB/worker boundaries; only external providers may be doubled in offline connected tests.
- Captured transport bodies, digest corruption, request counters and crash points prove recovery; manufactured missing imports do not.
- Concurrency tests use two independent processes/connections with a synchronized overlap; report losing operation and committed winner.
- Real browser tests record actual capture/check reports and preview frames; a mocked seven-pass object is not container evidence.
- Temporal tests use actual queues/Activities; inspect serialized event history, restart workers and replay captured history. No unconditional Activity success stubs.
- Treat skips separately. Live two-PDF/API gate must upload/process/generate/store/check/review a real disposable sample. A session check/empty notebook alone cannot pass it.
