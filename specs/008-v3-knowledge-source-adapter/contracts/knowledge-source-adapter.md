# Contract: 008 Private Source Handoff and KnowledgeSourceAdapter

**Version:** 008-r1. Reuse 004 active original-owner web boundary, 005 `SettingsVersionRepository::getCaptured`, 006 `AcceptedPdfReader::openForCase` and `v3_private` disk, and 007 `CaseWorkflow`, HMAC middleware, bridge, link and safe event projector. 008 adds no public PDF/NotebookLM URL, admin source API, teacher prompt action or future KOS/KIE service.

## Exact activation and worker transport

`php artisan v3:dispatch-sources` runs each minute and selects 007 links with matching committed case `state=queued`, `stage_code=extraction`, `start_state=started` and no terminal event. Under case/link lock it creates one `v3_source_activations` row and dispatches an after-commit `ActivateCaseSourceJob` on 007's `v3_workflow` queue. CAS lease is two minutes; duplicate jobs exit. A case/link changed to terminal before claim is not signaled. The existing workflow ID is never replaced. Laravel verifies the case's captured 005 checksum and the 006 same-owner ready Document before activation. Account suspension after workflow start does not change ownership or stop this already authorized automated work; 004 still denies the teacher's HTTP access.

Laravel uses 007's `V3_BRIDGE_HMAC_KEY` to call new private `POST /internal/v1/workflows/{workflow_id}/activate-source` with exact JSON `{schema_version:1,case_id:UUID,activation_id:UUID}`. The Python bridge describes that workflow ID, checks 007 memo case/settings identity, and calls `handle.signal("source_activation_v1", payload)`; 202 `{data:{workflow_id,activation_id,accepted:true}}` means Temporal accepted the signal, **not** that extraction ran. Missing/mismatched/closed workflow returns 409 `source_activation_conflict`; Temporal unavailable returns 503 `workflow_unavailable`. Timeout/5xx leaves activation `uncertain`. A minute reconciler may resend only the same activation ID; the deterministic workflow signal handler accepts its first matching case/ID, treats exact duplicate as no-op, ignores conflicting IDs, and does not run a second extraction. A 24-hour unresolved signal raises fixed `source_activation_overdue` warning, not a new case/ID. The signal carries no Document ID, path, PDF, text or provider ID.

The worker may call the PDF route while the activation row is still `signaling` or `uncertain` because Temporal can run the signal before Laravel receives its acknowledgement. Those states and `accepted` are valid for the **same** stored activation ID and fixed workflow; `pending` with no committed signal attempt is not. Worker access checks immutable case/Document ownership and captured settings, not the teacher's current login status. A late bridge response must not regress activation or case state.

Python→Laravel worker requests use 007's `V3_CALLBACK_HMAC_KEY`, timestamp/signature/version headers and signed raw-body rule; verify before ID lookup. Extend 007's HMAC-only `routes/api.php`. Internal JSON failures use `{error:{code,message}}` with fixed 401 `worker_unauthenticated` / `Worker authentication failed.`, 404 `source_unavailable` / `Source is unavailable.`, 409 `source_conflict` / `Source state changed.`, 422 `source_invalid` / `Source request is invalid.`, 503 `source_unavailable` / `Source is unavailable.` for temporary storage/DB outage, 503 `source_integrity_failure` / `Source integrity check failed.` for a verified missing/hash-mismatched accepted file, and 503 `settings_unavailable` / `Captured settings are unavailable.` for a verified missing/corrupt 005 row. Do not expose raw exception or provider text. All responses, including denials, are private/no-store. No browser cookie/session/CSRF authorizes these routes. A request to an unknown, foreign or stale activation gets the same 404 body as a missing one after valid worker authentication.

The Python worker spools the PDF into a mode-0600 temporary file outside any public root, verifies byte count/digest against response headers, and unlinks it in `finally`. No PDF bytes/path enter Temporal input/result/history, HTTP access logs or ordinary application logs. `GET` response body is not HMAC-signed; the transport must be loopback or TLS on private hosts, and Python checks the digest. Captured 005 settings are loaded by Laravel on every worker read; a missing/corrupt row fails closed.

## Extraction and canonical text gate

Use `pdfplumber` for the text layer and page geometry, Poppler `pdftoppm` plus Tesseract `pytesseract` for OCR; pin tested versions in `v3_engine/pyproject.toml` and record binary versions. The V2 extractor can guide fixture selection but is not imported: it writes arbitrary output paths and logs raw exceptions. The worker processes pages 1..the verified 006 page count, one page at a time. `page.extract_words` supplies coordinates; preserve headings and word text, read a detected two-column page left-column then right-column, otherwise order top-to-bottom then left-to-right. Extract table cells row-major through `page.extract_tables`, avoiding duplicate text from the same bounding boxes; if table boundaries or word placement cannot be resolved, record `structure_unrepresented` and block. A text page must retain every extracted word once, no U+FFFD replacement glyph, and at least one Unicode letter/number. A text-layer page with a nontext image or vector-drawing bounding region occupying at least 5% of page area outside text/table word boxes records `visual_unrepresented` and blocks because no faithful text representation exists.

If a page has no usable text layer, OCR the full page only while captured `limits.max_ocr_pages` remains. OCR output must contain at least one Unicode letter/number, average Tesseract confidence ≥70 on recognized tokens and no replacement glyph; otherwise record `unreadable`. Store confidence as a decimal 0–100 rounded to one decimal only for the page report; compare the unrounded value at the threshold. Render the OCR page at 200 dpi in grayscale. Mark pixels below grayscale 240 as foreground; exclude each accepted OCR word box expanded by 5 rendered pixels. If residual foreground occupies at least 0.2% of page pixels, or a residual connected component's bounding box occupies at least 1% of page area, record `visual_unrepresented` and block. This intentionally rejects scans with diagrams or unrecognized text rather than asserting that OCR covered them. OCR tool/language missing is `provider_unavailable`; no OCR budget is `validation`. A page with zero content, even if visually blank, is conservatively blocked. The pixel gate is a conservative detectable-gap rule, not semantic proof of every illustration; record method/confidence and include scanned diagram/formula fixtures. Any parser error, page mismatch, structural gap, over-1-MiB canonical text or unsupported source means `blocked` before `notebook_create`/`notebook_add_text`. Never truncate, summarize or skip a page to pass the gate.

Normalize text to UTF-8 NFC with LF line endings. Escape an original line matching `^\[/?PAGE [0-9]+/[0-9]+\]$` by prefixing `\`, then wrap page i of N in `[PAGE i/N]` and `[/PAGE i/N]` on separate lines, one page in order, with a final LF. `text_sha256` hashes these exact bytes. Each `PageReport` matches the model in [data-model](../data-model.md); the report has no raw text. Python posts a complete ready/blocked result. Laravel writes ready bytes to a temporary private file, fsyncs and atomically renames to `extracted/{case_id}/{digest}.txt`, then inserts the row and commits; a failed DB commit leaves an orphan for the minute `v3:reconcile-sources` command to purge after 24 hours. Duplicate exact POST reads/verifies the existing file and returns its ref. A changed result for the same case is `source_conflict`, never overwrite. No notebook call occurs until a ready row and private artifact verify.

## NotebookLM adapter and external-effect ledger

Use the selected package pinned to an exact released version, initially `@m4ykeldev/notebooklm-mcp@0.3.1`, over MCP stdio from the Python activity process. The adapter calls the tool by name with a strict input allowlist; no general agent chooses tools. At startup, inspect `tools/list` for required names and fields and compare to the pinned schema. Supply MCP session cookies through the worker's secret environment, not a repository auth file; never store them in settings/DB. Do not forward MCP stderr/tool arguments to ordinary logs: record only fixed operation/error codes and case/workflow IDs. Use only `notebook_create`, `notebook_list`, `notebook_get`, `notebook_add_text`, `source_get_content` and later `notebook_query`; no Drive, URL, research import or delete operation in 008. `notebook_add_text` uses `{notebook_id,content,title}` only; never `file_path`. A source document's apparent instructions remain untrusted data and cannot trigger another MCP tool.

Notebook title is exactly `v3-case-{case_id}`; source title is `v3-text-{case_id}-{first_16_hex_of_text_sha256}`. These contain no filename, teacher identity or educational text. Create one `KnowledgeSourceBinding` shell under case lock before the first MCP effect. For `notebook_create`, claim its effect before call. A successful response with one notebook ID is checked with `notebook_get` for exact title and an empty source list; then confirm effect and save the ID. If response is lost, reconcile `notebook_list` by exact title: exactly one candidate with empty source list and no other 008 binding may be adopted after `notebook_get`; zero or multiple candidates remain `notebook_uncertain`, with no automatic create retry. A notebook with unexpected sources or ownership metadata is conflict/blocked, not adopted.

For `notebook_add_text`, verify the ready artifact digest and claim once, then send exact canonical text. Set `send_attempted_at` and `transfer_status=uncertain` with the committed claim; this timestamp records an attempt, not proven delivery. The selected tool returns only `{message:"Text source added"}` and no source ID. After a success or ambiguous outcome, inspect only the bound notebook via `notebook_get`; for every exact-title candidate call `source_get_content`, normalize only line endings to LF, and require byte-for-byte equality to the canonical artifact. Exactly one matching source ID confirms the effect/binding/transfer. Zero or multiple matches, content mismatch, unavailable inventory or response schema drift remain `add_uncertain`/`transfer_status=uncertain`; never re-send automatically. The minute reconciler continues read-only checks and emits a fixed warning after 24 hours; it does not invent a provider ID. Operator remediation is outside 008's automatic API and must not silently change the case/source lineage.

`send_count=1` is a hard invariant for create/add even if a Temporal activity retries. Retry `notebook_list`, `notebook_get`, `source_get_content` and `notebook_query` with 007's captured `technical_retries+1` total attempts and exponential delay from `retry_delay_seconds`, capped at 3600 seconds. Rate limit/outage/session expiry are `provider_unavailable` and leave reversible read reconciliation; invalid installed schema is `policy_denied` and stops. A business gap/size failure is `validation` and never calls MCP. A successful tool message without content proof is **not** a confirmed transfer.

The ledger computes canonical request digests itself: `sha256("notebook_create\n" + case_id + "\n" + notebook_title)` or `sha256("notebook_add_text\n" + case_id + "\n" + notebook_id + "\n" + source_title + "\n" + text_sha256)`, all UTF-8. It rejects a caller digest that differs. `notebook_list` reconciliation requests the installed tool's maximum supported result count and treats a full/truncated result as incomplete; it can adopt one match only when the returned inventory is demonstrably complete. A 24-hour zero-match result remains uncertain even if a fake adapter reports immediate consistency.

## Typed adapter and 007 projection

`KnowledgeSourceAdapter.ingest(case_id:UUID, extracted_source_ref:UUID, activation_id:UUID) -> {binding_ref:UUID,status:"bound"|"uncertain"|"blocked",provenance:{adapter_kind,adapter_version,text_sha256}}`. It never returns notebook/source IDs to the workflow. `get_binding(case_id,binding_ref)` checks same case and returns only safe ref/status to workflow callers. `query(case_id:UUID,binding_ref:UUID,query_text:string,conversation_ref?:string) -> {answer:string,conversation_ref:string}` is an **activity-local** method for 009 to call; it resolves private provider IDs from Laravel's case-scoped worker-only binding endpoint and passes `source_ids:[bound_source_id]` to `notebook_query`. Reject empty/oversize query (>16,384 UTF-8 bytes), unknown binding and cross-case caller; no source ID supplied by the caller is accepted. The raw answer is not returned as a Temporal activity result or exposed by 008 HTTP; 009 owns its private answer persistence and canonical prompt/Section workflow. 008's test-only query fixture proves scoped MCP call and conversation pass-through, not NotebookLM mapping.

008 extends 007's signed event projector with `source_blocked` (only `stage_code=extraction|sourcing`, `status_code=blocked`, `error_code=validation|provider_unavailable|internal|policy_denied`) after validating 008 activation/extraction/binding provenance. `source_blocked` transitions `queued|running → blocked` once and is terminal in 008. Normal safe milestones are `stage_started/extraction/running`, `stage_completed/extraction/queued`, `stage_started/sourcing/running`, `stage_completed/sourcing/queued`. Event keys are exactly `source:extraction:started`, `source:extraction:completed`, `source:sourcing:started`, `source:sourcing:completed`, `source:blocked:extraction`, or `source:blocked:sourcing`; 007's `(case_id,event_key)` uniqueness applies. Start from the 007 `workflow_started` callback's returned case version 2, then use each accepted/duplicate callback's returned version as the next expected version. A lost acknowledgement retries the **same** key/payload; never guess a later version or include raw metadata. A provider outcome still uncertain keeps the case `running`/delayed and the source run `uncertain`; it does not falsely send `source_blocked`. After bound, `CaseWorkflow` parks at a deterministic 009 mapping handoff; 009 replaces that wait in a replay-compatible rollout. 008 does not produce a learning map or Section.

Failure projection is fixed: unreadable/visual/structure/page/size gap is `source_blocked/extraction/validation`; verified `source_integrity_failure` or `settings_unavailable` is `source_blocked/extraction/internal`; missing OCR binary/language is `source_blocked/extraction/provider_unavailable`; installed MCP schema mismatch before any provider send is `source_blocked/sourcing/policy_denied`. A temporary PDF-stream I/O outage uses captured technical retries and stays running/delayed while unresolved. A known pre-send provider outage after captured technical retries is `source_blocked/sourcing/provider_unavailable`. Once a create/add send claim exists, an outage or ambiguous outcome remains `running`/delayed with private `uncertain` evidence and no terminal blocked event. An offline worker with no verified failure is likewise delayed, not failed. Once bound, 008 parks with `await workflow.wait_condition(lambda: False)`; 009 replaces this line in a replay-compatible rollout and owns an authenticated `mapping_activation_v1({case_id,binding_ref,activation_id})` delivery. 008 has no production mapping signal handler or sender.
