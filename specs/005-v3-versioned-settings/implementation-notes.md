# Repository Notes for the 005 Implementer

`routes/web.php` currently mixes legacy admin, teacher and content routes. 004 plans a separate `routes/v3.php`; append settings routes there after it exists. The legacy `role:admin` check sees role only, and `TeacherAccessMiddleware` explicitly grants admins access to teacher content. Neither is the V3 settings gate. Use 004's fresh active-admin resolver and its private response/error behavior for every settings route, including denied GET/POST.

The users migration supplies a bigint user ID and enum `admin/teacher/student`; there is no global active flag. 004's access row determines pilot enrollment/activity. A settings publish must reload that state while holding the access-control lock, not rely on a session's cached role. Do not grant teacher access to settings or use admin identity as a worker credential.

SQLite is the test default. `SELECT ... FOR UPDATE` alone is insufficient for the documented two-admin race. The pointer singleton's first write serializes both publishers and case selection, and transaction rollback must include version, pointer and publication event. Keep the pointer's `revision` distinct from the public settings `version`. The checksum covers canonical normalized payload bytes; array order, especially `coding_order`, is meaningful.

No V3 provider secret is configured in `config/services.php` or `.env.example` yet. 005 accepts only fixed credential-reference labels and never resolves or stores secret values. Do not log a rejected publish request or include request fields in exception/audit context. The `User` model is serializable; use an explicit settings resource instead of returning models with relationships. Publication audit records field paths only. Retain all versions for later case lineage.

The owner chose approved-template selection. `Google-Ai-studio-System-prompts` is an untracked candidate, not an approved default, and no approved feedback file was found. The trusted CLI import verifies exact bytes/digest and writes an immutable catalog row. The admin form shows IDs/digests only and cannot edit or read bodies. Do not seed a guessed instruction, copy V2 text into production or let a request upload template text. Tests may create isolated approved fixture bodies; record that actual first publication needs operator-imported, owner-approved feedback and scene files.

006 owns `ProcessingCase` and its route/idempotency behavior. A 005 fixture consumer proves only the selection/read contract; keep it under `tests/`. 006 must call selection in its case transaction and retain the selected ID. 007/010–013 consume that ID on every retry/review. A missing version or selected template is a block, never a reason to read active settings or a newer template. Provider outages use the captured order; JEV typed decisions are applied directly; NotebookLM's mapping and 009's canonical prompts are unaffected by settings.

The first publication is an operator action, not a migration default. An empty pointer is a valid admin empty state and an expected case-start failure. Treat 004 or external provider unavailability as the specific prerequisite/runtime condition it is, rather than adding a fake production placeholder.
