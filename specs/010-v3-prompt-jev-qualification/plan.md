## 1. Work item and canonical generation

Read the exact current 009 context and 010 private Section/Continue context. `PromptContextReader` checks case, 008 bound source, 009 `awaiting_010`, map/work/Section relationships, all eleven fields and answer digest; its HMAC route is the only 010 source of raw First/Continue data. The work-item claim captures 009 cursor version and ordered Section refs. Canonical byte assets are copied from 009's fenced blocks at implementation and checksum-tested; do not copy-edit text.

`cycle.py` asks `query_once` for exact Execution once after 009's first First response. `System Ready` leads to sent Second/Third; a complete same-work combined Execution answer is reused for those steps. For a later `Continue`, `parser.py` first checks the recorded raw reply; complete combined later material is reused with no send, First-only reply leads to staged Second/Third sends, and partial later material blocks. Every sent turn follows a committed Laravel claim. Verify each step's conversation ID and full exact Section set. `RecordPromptTurn` stores private raw answer and parsed lineage; Third commits all version-1 prompt rows and Section pointers together. `PromptReceiptSender` uses the exact 009 completion digest/Section order and stable completion ref. It sends after storage commit and replays only the identical receipt if acknowledgement is lost. The workflow then allows per-Section JEV to proceed; 009 may separately progress to next work. There is no second lesson cursor or extra prompt-generation model call; `providers.prompt` is captured but unused in 010 by explicit owner decision.

## 2. JEV and decision policy

`jev.py` uses official Bearer `/v1/systemone`, explicit deployment `TYPESAFE_API_KEY` and `JEV_MODEL`, and exact named questions in the contract. The worker builds the request from signed private qualification context, computes a stable request digest and claims an attempt. `policy.py` and Laravel `RecordPromptQualification` implement the same golden fixtures: three exact named typed answers, 0–100 Score levels, inclusive captured score/confidence thresholds, Noul yes/confidence interpretation, Choice `block` terminal precedence and revision exhaustion. Laravel recomputes the verdict from raw typed values and captured 005 row; the worker cannot POST its own `pass` flag. A vendor wire mismatch is a technical failure, not a failed prompt. Do not use an additional model to judge JEV.

JEV evaluation is read-only, so captured `technical_retries+1` attempts can repeat the identical request after transport failures; `retry_delay_seconds` is the base of 007's backoff. One valid response commits an immutable qualification under Section lock; duplicate exact response returns that ref and a changed response conflicts. An unavailable JEV or mismatched model/credential never opens 011. Verify the installed model with `/v1/models` at the live gate; do not claim a published 005 settings version proves account health.

## 3. Feedback revision and 011 handoff

Only a current nonpassing version with a nonterminal decision and available revision budget can claim feedback. Fetch exact bytes via 005 `ApprovedTemplateRepository::getCaptured` and exact captured `providers.feedback`; no default/fallback. Use `FeedbackTextAdapter` and fixed Gemini/Z.AI/DeepSeek nonstreaming request/response mappings in the contract, with official-schema fixtures for each ID. Claim once before generation; a post-send timeout stays uncertain because the provider's effect idempotency is not established. A known result is checked for a single replacement prompt body, same Section and structural scene type, then private raw response/output files + successor row + current pointer commit atomically. It does not alter 009 Section fields or predecessor. Each successor re-enters JEV. `QualifiedPromptResolver` serves only a current same-Section version with a recorded pass to 011's signed worker, rehashing the private body. 011 must still bind this ref to its own authoring request and must never trust a supplied `pass` flag.

## 4. State, authorization and recovery

Use the exact provenance-checked 007 event keys and safe codes in the contract; do not add educational values to Temporal activity arguments/results, event payloads, admin DTO or logs. Section state is independent of case-level progress. A blocked Section does not cancel siblings or undo 009 receipt; the owner-only `/prompt-status` route shows per-Section safe status while admin retains only case metadata. No teacher prompt review/edit route and no admin content route. The 004 original-owner chain guards that new route and existing 009 Section/progress routes; regress actual V2 routes against V3 UUIDs. The signed internal routes check HMAC before any ref lookup and never accept a client owner/source ID.

For an uncertain sent NotebookLM/feedback call, read-only reconciliation may accept the exact recorded response if available, but does not resend. A missing/corrupt referenced artifact fails closed. Orphan private files older than 24 hours are removable only after DB reference check; all committed evidence and unresolved attempts remain for 015. 014 defines reviewed operator repair. Technical failures before send use captured 007 budget; deterministic parser/source/policy failures are nonretryable. A case with a remaining qualified or pending Section is not marked terminal merely because one Section blocked.
