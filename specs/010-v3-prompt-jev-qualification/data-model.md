# Data Model: 010 Prompt Turns, Versions and Qualification

Create these new tables in one 010 migration series after 009. UUIDs are server generated `char(36)`; all case FKs reference `v3_processing_cases.id` with restricted delete. Parent checks require the same case/map/work/Section under a DB transaction; a bare UUID is never authority. No owner column is copied: the immutable original teacher is resolved through the case. No V2 model/table is reused. Store bodies and raw answers on 008's private `v3_private` disk, not in JSON DTOs or Temporal histories. Every referenced artifact is rehashed on read.

## `v3_prompt_work_items` — `App\Models\V3\PromptWorkItem`

`id` UUID PK; `case_id` FK; `map_id` FK `v3_lesson_maps.id`; `work_node_id` FK `v3_lesson_nodes.id`; `work_ordinal` unsigned integer; `expected_cursor_version` unsigned bigint; `section_query_id` FK `v3_lesson_queries.id`; `state` `awaiting_execution|awaiting_second|awaiting_third|originals_ready|receipt_committed|uncertain|blocked`; nullable `execution_turn_id`, `second_turn_id`, `third_turn_id`, `completion_ref` varchar(255), `completion_sha256` char(64), `final_conversation_id` varchar(255), `last_alert_code` varchar(32), `last_alerted_at`, `receipt_committed_at`; timestamps. Unique `(case_id,work_ordinal)`, `(case_id,completion_ref)` when non-null. Creation snapshots the exact current Section IDs **in ordinal order** in `section_refs` JSON and 009 cursor version. It cannot be created from an old cursor or altered Section set. The row is the case lock target for Second/Third claims and completion.

## `v3_prompt_turns` — `App\Models\V3\PromptTurn`

Work item 1 starts `awaiting_execution`; later work starts `awaiting_second` only after its recorded 009 Continue answer has been inspected. An Execution turn is sent once for work 1. A complete combined Execution reply may supply `execution_reuse` Second/Third turns referencing its recorded turn; a complete combined Continue reply supplies `continue_reuse` turns referencing the recorded 009 query. Either reuse copies/verifies raw answer privately and never increments `send_count`. The `section_query_id` is the 009 First query for work 1 or its recorded Continue query for later work. Create self/feedback FKs after the referenced tables exist in the migration; do not weaken them to polymorphic strings.

`id` UUID PK; `work_item_id` FK; `step` `execution|second|third`; unique `(work_item_id,step)`; `origin` `sent|execution_reuse|continue_reuse`; nullable `origin_query_id` FK `v3_lesson_queries.id` only for `continue_reuse`; nullable `origin_turn_id` self FK only for `execution_reuse`; `state` `claimed|uncertain|recorded|blocked`; `send_count` unsigned tinyint 0 or 1 (0 for either reuse); `request_sha256`, `canonical_sha256`, nullable `answer_sha256` char(64); `conversation_in`, nullable `conversation_out` varchar(255); nullable `answer_path` varchar(255), `answer_bytes` unsigned bigint, nullable `parsed_mappings` JSON (Second only), `sent_at`, `recorded_at`; nullable safe `error_code` varchar(32); timestamps. `request_sha256` binds case, map/work/Section IDs, step, exact canonical digest and conversation input. A `sent` turn commits claim and `send_count=1` before `query_once`; a `continue_reuse` turn points to the exact recorded 009 Continue query and cannot send. State transitions: `claimed→recorded|uncertain|blocked`, `uncertain→recorded|blocked` only with exact same known response; `recorded` immutable. Raw answer ≤4 MiB to `prompt-turns/{case_id}/{turn_id}/{digest}.txt`; private temporary write, fsync, atomic rename, then DB commit. A failed DB commit leaves a purgeable unreferenced file, never a recorded turn. No automatic resend after claim.

## `v3_scene_prompt_versions` — `App\Models\V3\ScenePromptVersion`

`id` UUID PK; `case_id` FK; `work_item_id` FK; `section_id` FK `v3_teacher_sections.id`; `version_no` unsigned smallint ≥1; nullable `predecessor_id` self FK; `origin` `third|feedback`; nullable `third_turn_id` FK for version 1; nullable `feedback_effect_id` FK for successor; `body_path` varchar(255), `body_sha256` char(64), `body_bytes` unsigned integer 1..65536; `scene_type` `Process|Comparison|Accumulation|Parallel Flow|Time Evolution`; `section_fields_sha256`, `canonical_third_sha256` char(64); `created_at`. Unique `(section_id,version_no)`, `(section_id,body_sha256,version_no)` and `(work_item_id,section_id,version_no)`; one version 1 per Section. Version 1 has predecessor null and exact Third-turn origin; later versions have predecessor=`version_no-1` for the same Section and one recorded feedback effect. Content/lineage immutable after insert; no `updated_at` or soft delete. An identical revision callback returns the existing ID, never creates version `n+1` twice. `third_output_refs` in 009's receipt are these version-1 IDs, not arbitrary strings.

## `v3_prompt_jev_attempts` and `v3_prompt_qualifications`

Attempt columns: `id` UUID PK; `prompt_version_id` FK; `attempt_no` unsigned smallint; `request_sha256`, `question_sha256` char(64); `requested_model` varchar(100); `settings_version_id` FK `v3_settings_versions.id`; `state` `claimed|technical_failure|recorded`; nullable HTTP/provider safe `error_code` varchar(32), `sent_at`, `finished_at`; unique `(prompt_version_id,attempt_no)`. All attempts for one version have the same request digest and model/question/settings identity; max rows `technical_retries+1`. A timeout may be retried because JEV evaluation is read-only; no technical attempt writes a verdict.

Qualification columns: `id` UUID PK; `prompt_version_id` unique FK; `winning_attempt_id` unique FK; `case_id`, `section_id` FKs; `settings_version_id` FK `v3_settings_versions.id`; `settings_checksum`, `request_sha256`, `answer_sha256`, `question_sha256` char(64); `rule_version` varchar(32) fixed `prompt-rule-v1`; `requested_model`, `returned_model` varchar(100); `choice` `pass|revise|block`; `choice_confidence` decimal(20,18); `score` decimal(21,18); `score_confidence` decimal(20,18); `noul_probability` decimal(20,18); `noul_yes` boolean; `min_score`, `min_confidence` unsigned tinyint; `decision` `pass|revise|block`; `failed_checks` JSON array of fixed codes; `answer_path` varchar(255) private; `created_at`. All comparisons use original numeric response values before any display rounding. Raw answer ≤1 MiB, stored atomically/private and hashed. The first valid committed answer is final for that version; changed replay conflicts. A `pass` is valid only if every captured check passes and the row's version is current for the Section. Old passes remain evidence but lose handoff eligibility after a successor is inserted.

## `v3_prompt_feedback_effects` — `App\Models\V3\PromptFeedbackEffect`

`id` UUID PK; `case_id`, `section_id`, `from_prompt_version_id` FKs; unique `from_prompt_version_id`; `request_sha256` char(64); `template_id` varchar(64), `template_sha256` char(64); `provider_id` `gemini_api|glm_api|deepseek_api`, `provider_model` varchar(100), `credential_ref` varchar(32); `state` `claimed|uncertain|recorded|blocked`; `send_count` unsigned tinyint 0 or 1; nullable `output_path` varchar(255), `output_sha256` char(64), nullable `response_path` varchar(255), `response_sha256` char(64), `returned_model` varchar(100), `provider_response_id` varchar(255), `output_bytes` unsigned integer, `to_prompt_version_id` UUID FK; nullable safe `error_code`, `sent_at`, `recorded_at`; timestamps. Claim is committed before a model call. Technical failure before send can use captured retry budget; after possible delivery it is uncertain and cannot be sent automatically again. Feedback output is private, max 65536 UTF-8 bytes. The result write, successor insert, and Section-current pointer change occur under one case/Section lock; no forked revision chain.

## `v3_prompt_section_states` — `App\Models\V3\PromptSectionState`

The feedback `response_path` stores the exact selected-provider JSON on `v3_private` (≤1 MiB), separate from the normalized replacement text at `output_path`; both digests are verified before a successor is committed. Provider response ID/model are private lineage, never admin or teacher response fields.

`section_id` UUID PK/FK; `case_id` FK; `current_prompt_version_id` nullable FK; `status` `awaiting_prompt|awaiting_qualification|revising|qualified|uncertain|blocked`; `revision_count` unsigned smallint default 0; nullable `last_qualification_id` FK, safe `error_code` varchar(32), `last_alert_code`, `last_alerted_at`; timestamps. Under Section lock, increment `revision_count` only when a successor version commits. Require `revision_count ≤ captured limits.prompt_revisions` and `current_prompt_version_id` for `qualified`. A qualified resolver checks state, current version and its unique pass row in the same transaction; it never accepts a stale ID or client-supplied pass flag.

## Retention and indexes

Index work-item `(case_id,state,work_ordinal)`, turn `(state,sent_at)`, Section-state `(case_id,status)`, and attempts `(state,sent_at)`. Keep all rows and referenced files while the case exists, and all uncertain effects/attempt evidence. A 24-hour orphan cleaner may remove only unreferenced temporary files after DB lookup; 015 owns later retention/export. Log safe fixed codes plus case/work IDs, not Section/prompt/provider/source text, artifact paths, answer bodies or credentials. Suppress repeat unresolved-condition warnings to once per 24 hours per Section/work row.
