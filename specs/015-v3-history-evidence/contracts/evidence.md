## HTTP routes and access

Append to 004 `routes/v3.php` using the real `web` session, CSRF for POST, fresh 004 active role/owner policy and `Cache-Control: private, no-store` for every success/error/denial. All UUIDs are canonical lowercase UUID strings; malformed IDs are 404. JSON successes use `{data:...}`. HTML GET renders the same allowlisted data in V3 views. Never pass a loaded Eloquent model/relation to a view or serializer. Existing `/users`, `/subjects`, `/lectures`, `/sections`, `/questions`, `/exam_questions`, `/api/*`, 006 download and 013 review paths keep their existing gates and must not query 015 snapshots by ID.

POST validators reject extra business fields including owner ID, actor, provider, path, serializer, cost or content. `_token` is a framework field. Browser POST success redirects 303 to its authorized download endpoint; JSON uses statuses above. `download_url` is a normal route requiring fresh session authorization, never a bearer capability. Owner case export covers all committed case branches/events and safe content refs; approval export narrows to one chain plus its revisions. No raw content bytes, note bodies, provider answers or private paths appear in either. If a source has an existing owner-authorized route (for example 006 document download or 013 review), `content_ref` is that ordinary route plus `content_state`; otherwise it is null with an opaque kind/ref. Admin has a separate aggregate serializer defined below; it cannot serialize `EvidenceGraphV1` or arbitrary nested metadata.

`EvidenceNodeV1` has exactly `{kind,ref,state,recorded_at,content_state,content_ref}`; `content_ref` is nullable and nonnull only for a verified available artifact with an existing owner-authorized route. `EvidenceLinkV1` has exactly `{from_kind,from_ref,to_kind,to_ref,relation}`, where `relation` is a named prerequisite FK/pointer from the inventory; `EvidenceGapV1` has exactly `{code,parent_ref}` with the fixed codes in [data-model.md](../data-model.md). `EvidenceGraphV1` has exactly the fields listed there, ordered by prerequisite stage then committed timestamp/ref. `EvidenceEventV1` has the node fields plus `event_type` from 007/014 fixed codes; no JSON `metadata` bag is permitted.

`AdminMetricReportV1` has exactly `{schema_version:1,from,to,as_of,case_count,outcomes,current_approved_scene_count,historical_approval_count,technical_retry_count,prompt_revision_count,scene_repair_count,teacher_change_count,case_elapsed_ms,stage_residence_ms,operation_observed_ms,review_wait_ms,usage,cost,gap_count}`. `outcomes` is a map of the 004 status codes to nonnegative counts. Each duration field except `stage_residence_ms` is `{sum:null|nonnegative_integer,known_count,unknown_count,ongoing_count,definition}`; stage residence is a map of 004 stage codes to that shape. `usage` is `{known_input_tokens,known_output_tokens,unknown_operation_count}` with integer counts; known sums never imply a complete total when unknown count is nonzero. `cost` is `{status:"actual"|"estimated"|"unknown",known_subtotals:[{currency,amount_minor}],unknown_component_count,full_amount_minor:null|integer,currency:null|string,per_current_approved_scene_minor:null|decimal_string,per_scene_reason:null|"no_current_approvals"|"unknown_components"|"currency_mismatch"}`. The quotient is rounded half-up to six fractional minor-unit digits for reporting only; include the exact `full_amount_minor` and `current_approved_scene_count` so it can be recomputed. Known subtotals are sorted by currency and may be empty. No owner/account/case/Section/approval IDs, teacher names or titles occur in this aggregate response/export; 014 owns per-case operational IDs. Admin export wraps the exact report as `{schema_version:1,scope:"admin_period",report:AdminMetricReportV1}`. Owner export wraps `{schema_version:1,scope:"owner_case"|"owner_approval",graph:EvidenceGraphV1,metric:CaseMetricReportV1}`, where `CaseMetricReportV1` has exactly `{case_ref,as_of,outcome,current_approved_scene_count,historical_approval_count,technical_retry_count,prompt_revision_count,scene_repair_count,teacher_change_count,case_elapsed_ms,stage_residence_ms,operation_observed_ms,review_wait_ms,usage,cost,gap_count}` with the same nested shapes. The JSON key set is closed recursively.

## Metric definitions

All times are UTC and nonnegative, calculated from committed server timestamps at a fixed `as_of`. `case_elapsed_ms = (terminal 007 event.recorded_at or as_of) − 006 case.created_at`; if terminal proof is absent, mark ongoing or unknown rather than use `updated_at` as completion. `stage_residence_ms` uses each ordered 007 case-event boundary and the next event/as_of, with initial interval starting at case creation; it is time in recorded stage, including waits. `operation_observed_ms` is `finished_at−sent_at/started_at` for a single exact 008–013 attempt when both exist; this includes network/callback delay and is not billed compute time. 011 `duration_ms` and 012 check-run `duration_ms` are separate provider/checker reported durations; do not add them to case elapsed. `review_wait_ms = decided_at−ready_at` for a decided 013 item, including dormancy; pending items expose elapsed wait through `as_of` with `ongoing:true`. Active human labor time is unknown because 013 has no work timer. Negative/inverted boundaries are an `invalid_time` gap, not clamped zero.

Counts are from committed source rows: technical retries = number of actual attempts after ordinal 1 per operation; prompt revisions = successor `v3_scene_prompt_versions` per Section; scene repairs = committed `v3_scene_repairs`; teacher change requests = 013 `request_changes` decisions plus post-approval corrections; historical approvals = approval rows; current approvals = `v3_review_section_states.current_approval_id` pointing to valid row while case not cancelled. Never use 007 projection counts if they disagree with sources; flag `count_mismatch` and use verified source count. Period membership is case `created_at ∈ [from,to)`; open cases remain in outcome counts. An empty period returns zero counts and null ratios, not a zero per-scene cost.

Usage is read from 011 `input_tokens/output_tokens/cost_minor_units/currency/duration_ms`, 010/012 retained JEV `usage` only when its verified raw response contains numeric fields, and other verified source responses only if their prerequisite contract records a typed quantity. NotebookLM 008/009 and teacher labor normally have no measured usage/cost. Each possible charged effect is identified by immutable attempt/effect ID so retries and exact callbacks are counted once. Do not infer a tariff from model name, tokens, time or settings. A reported currency amount is `actual` with basis `provider_response` (a provider-reported amount, not an independently audited invoice). If every charge component is known in one currency, full case cost is their sum; otherwise null `unknown_components` with known subtotal. `estimated` is reserved for a future owner-approved versioned rate basis and is not emitted by the pilot. Period cost includes unsuccessful cases in its numerator as [spec.md](../spec.md) defines; mixed currencies return `currency_mismatch`, zero current approvals `no_current_approvals`.

## Error, replay and privacy rules

Check session → fresh active role → owner case/admin scope → child/export identity → input → snapshot/version. CSRF may reject before controller. JSON error is `{error:{code,message}}` with fixed text and no IDs/details. Guest 401 `unauthenticated`; inactive/wrong role 403 `access_denied`; missing/foreign case, approval or export 404 `resource_unavailable` (same body); malformed/extra input 422 `contract_invalid`; changed idempotency key or concurrently invalidated current approval for a new request 409 `evidence_conflict`; 10 MiB snapshot 413 `evidence_too_large`; own expired export 410 `evidence_expired`; DB/audit/private-storage corruption 503 `evidence_unavailable`. A trace with an existing approval but broken evidence returns 200 with `integrity:"incomplete"` and fixed gap codes, never a false complete chain. A missing/corrupt snapshot returns 503, never partial bytes. Admin sees only gap counts, not owner IDs, private refs or gap paths. Do not log raw request/response, export bytes, source/scene/note hash or full URL.

Exact create replay uses actor-scoped key plus canonical SHA-256 over validated fixed-order JSON, rechecks current access, returns original export metadata even if its 15-minute download has expired, and never creates a second file/audit. Changed same-key body is 409. A new key snapshots new state. Concurrent same-key calls produce one row/file and one `generated` audit; different keys are independent. A download rechecks current access, original actor, case ownership, expiry and file digest every time; disabling/role-changing an actor stops both replay and download. No public cache, CDN or storage link serves the file.

## Retention

`pilot-retain-v1` has no physical deletion of referenced 006–014 evidence. A 014 `deferred_to_015` assessment remains an assessment and may be displayed as a fixed operational event. History/export render `content_state` based on verified referenced private bytes; `missing_or_corrupt` is an incident, not proof of intentional deletion. Only 015 export JSON files expire and are purged as specified in [data-model.md](../data-model.md). A future deletion policy needs separate owner approval, a revised contract and a recheck of all active/uncertain/evidence holds.
