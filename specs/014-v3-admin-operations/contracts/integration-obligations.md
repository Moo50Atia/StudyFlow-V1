# 014 Foundations and Downstream Obligations

After implementation and its live gate, 014 supplies a closed metadata-only admin operations projection, case-locked operational control fence, immutable audited command/reminder/assessment rows and proof of matching Temporal control consumption. It does **not** give admins educational content, teacher-review authority, an export, a new provider send, a replacement terminal case run or a physical deletion API.

| Consumer | May use from 014 | Must still implement and prove |
|---|---|---|
| 015 history/evidence | Opaque command/control/reminder/assessment refs, fixed action/reason/status/error, actor/time and 004 ClosedSummary; `pilot-retain-v1` deferred assessment | Separate owner detail and admin redacted export serializers. Report hold/cancel/retry/reminder provenance and unknown cost honestly. Recheck all active workflow/review/effect/evidence references and a concrete retention policy before any physical deletion. An old `deferred_to_015` snapshot is never a delete authorization. Do not place teacher source, prompt, Section, scene, note, provider output, hash or private path in admin export. |
| Later student delivery | Current 013 approved Section pointer only if case remains eligible and not cancelled | Separate publication/access rule. A 014 admin action never approves or publishes a scene. |

004 remains the authority for active role, original owner and account access. 005 remains the authority for versioned settings. 007 retains fixed case workflow identity and immutable case events. 008–013 retain their own effect ledgers and content evidence; 014's `retry`/cancel fencing may call them only through the proved extension points in the [contract](admin-operations.md). The original teacher's 013 review is never transferred after account suspension or reminder. V2 paths are not adapters for V3 content.
