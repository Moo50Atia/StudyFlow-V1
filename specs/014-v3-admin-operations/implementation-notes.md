# Repository Notes for the 014 Implementer

- `app/Http/Controllers/UserController.php` currently writes `User` directly, and legacy `routes/web.php` mounts `/users` behind `role:admin`. 004 must first route those writes through `ChangeAccountAccess`, including fresh active-admin check and enrolled-account retention. 014 tests the real route; adding another account controller creates an avoidable bypass. `TeacherAccessMiddleware` allows V2 admin/student reads and does not grant V3 source/scene access.
- 004 ClosedSummary has an exact field allowlist. Build the 014 wrapper from scalar query selections and fixed enums only. Never pass `ProcessingCase::toArray()`, eager-loaded review/effect rows, raw exception text or an arbitrary `metadata` key. 015 will build its own export; 014 has no export endpoint.
- 007 case `state_version` belongs to immutable worker/event sequencing. Keep `control_version` separate for hold/resume. Cancellation alone creates a proof-backed terminal case event. A bridge 202 means delivery was accepted, not that the control took effect.
- Put `CaseOperationGuard` **inside** each case-locked effect-claim/teacher-decision transaction. A controller-only check races a worker claim. The guard stops new effects; it does not erase a provider call already sent. Known late results follow the original ledger and remain private, with no successor after cancellation.
- Existing 008 `notebook_create`/`notebook_add_text`, 010 feedback, 011 coding and 013 teacher-correction sends are one-send effects. An admin `retry` may query/read/reconcile the same identity; it never raises `send_count`, selects a new provider or creates a substitute prompt/candidate. 012 browser/JEV retries remain bounded by the case-captured technical budget.
- A disabled original teacher retains 006 ownership and 013 pending review. The reminder is fixed in-app text shown only through the restored original owner's workspace. Admin cannot view or submit 013 review, preview or note routes.
- `phpunit.xml` uses SQLite `:memory:`. The hold-versus-owner/send race must run against a shared transactional database with separate processes. The live Temporal worker gate proves signal/fence behavior; a controlled test activity does not prove an actual model provider was called.
- `pilot-retain-v1` records no automatic deletion date. 014 assessments are audit snapshots, not cleanup jobs. 015 must define/recheck a concrete retention policy before any later physical deletion, while preserving referenced and uncertain evidence.
