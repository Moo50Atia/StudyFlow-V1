# Contract: V3 PDF Intake and Processing Cases

**Version:** 006-r1. This extends the 004 `web` session, active-teacher, ownership, error and `Cache-Control: private, no-store` contract. It consumes the 005 settings v1 payload and `SelectCaseSettings`; no client owner, settings version or state is trusted.

## Routes and response envelope

Append to 004's `routes/v3.php` under its active-teacher middleware alias. Keep normal `web` CSRF for POST. Route UUIDs are canonical lowercase UUID strings; malformed UUID is 404. JSON successes use `{ "data": ... }`. Every listed response, including errors, is private/no-store. HTML uses 004's V3 layout on the same GET routes. Extend `resources/views/v3/teacher/workspace.blade.php` with a multipart upload form and link to the own attempt list. Render own list/detail/receipt in `resources/views/v3/teacher/{pdf-uploads/index,pdf-uploads/show,cases/show}.blade.php`. A pending detail shows a refresh link; an accepted detail with no prior case shows a `process` form; with a prior case it shows an open-previous GET link and a `process_again` form. Each rendered case form contains a fresh server-generated UUID idempotency key, retained on form resubmit. No raw filename/hash/path appears. Browser upload POST that created an attempt returns 303 to its detail even if application validation blocked/rejected it, so the page shows the safe reason; JSON status/code semantics below remain normative. Browser case POST success/replay returns 303 to the case receipt; conflict returns a generic 409 page with a reload link. CSRF and 004 denial/error rendering remain in force.

| Method/path | Name | JSON success |
|---|---|---|
| POST `/v3/teacher/pdf-uploads` | `v3.teacher.pdf-uploads.store` | 202 `{data:{attempt_id,state:"quarantined",status_url}}` after complete private staging; application rejection uses error response with `attempt_id` |
| GET `/v3/teacher/pdf-uploads` | `v3.teacher.pdf-uploads.index` | 200 `{data:[AttemptSummary],pagination:{page,per_page:20,has_more}}`, newest `created_at,id` first, owner filter before pagination |
| GET `/v3/teacher/pdf-uploads/{attempt}` | `v3.teacher.pdf-uploads.show` | 200 `{data:AttemptSummary}` |
| GET `/v3/teacher/documents/{document}/download` | `v3.teacher.documents.download` | 200 `application/pdf` byte stream, `Content-Disposition: attachment; filename="source.pdf"`, `X-Content-Type-Options: nosniff`; never a redirect or storage URL |
| POST `/v3/teacher/cases` | `v3.teacher.cases.store` | 201 `{data:CaseReceipt}` for new; 200 same receipt for identical idempotent replay |
| GET `/v3/teacher/cases/{case}` | `v3.teacher.cases.show` | 200 `{data:CaseReceipt}` for owned case; 007 extends progress separately |

`AttemptSummary` has exactly `attempt_id,state,reason_code,document_id,duplicate,latest_case_id,created_at,finished_at`; nullable values are explicit. `document_id` is non-null only on accepted attempts. `duplicate` is a boolean only when accepted, otherwise null. `latest_case_id` is the newest same-owner case for that Document, ordered by `created_at DESC,id DESC`, otherwise null. Never include filename, byte count, hash, page count, settings, path, parser/scanner output or raw PDF in JSON. `CaseReceipt` has exactly `case_id,document_id,state,settings_version_id,created_at`; initial state is `awaiting_workflow`; 007 later extends the state vocabulary. Replay/GET return the persisted current state.

## Upload request and validation

Multipart body contains exactly one `pdf` file. Framework `_token` is exempt from unknown-field detection. No owner, filename override, document ID, URL, path, MIME override or settings ID field is accepted. Application code creates a UUID attempt immediately after 004 actor authorization, before business validation, using the authenticated user's current `id`. Validate application fields only after that insert; a Laravel FormRequest that rejects before controller entry would violate the attempt-ID contract. Missing active 005 settings creates an attempt with `upload_settings_version_id=null`, state `blocked`, reason `settings_unavailable`, then returns 503. A bad multipart file or invalid field returns 422 `upload_invalid` with the attempt ID. Rejection for an inspected file appears on polling with state/reason; initial complete staging returns 202. A controller-detected incomplete transfer returns 422. Bodies rejected before Laravel controller entry by PHP/web server cannot produce an attempt; deploy web/PHP limits above 005's maximum 100 MiB plus multipart overhead (for example 110 MiB), and do not claim otherwise.

The upload-time active 005 version is captured before reading bytes. In one short transaction, first-write the 004 access singleton and recheck the teacher, create the attempt, then call 005 `SelectCaseSettings` on the same connection to select the active immutable row. Save its ID on the attempt. Catch typed settings unavailability inside this transaction, mark this attempt blocked and commit it; no bytes are read. Publication and upload selection therefore serialize in the same lock order. Use `limits.max_pdf_bytes` (1–104857600) and `limits.max_pdf_pages` (1–1000). Stream through a bounded read to `v3_private/quarantine/{attemptUUID}.pdf`; abort and purge on over-limit or interrupted upload. Require positive received size, PHP upload success, final filename extension `.pdf` case-insensitively, and `%PDF-` at byte offset zero. Client MIME is untrusted and is never an acceptance gate. A 0-byte file, missing multipart part or extra application field is `upload_invalid`; over-limit is `size_exceeded`.

Validation runs against the same quarantined bytes and version: qpdf CLI version 11+ with JSON v2 support, invoked via Symfony Process argument arrays. `qpdf --is-encrypted` must return exit 2 (unencrypted; exit 0 means encrypted); `qpdf --check` must exit 0 (warnings exit 3 and are rejected); `qpdf --show-npages` must parse a positive integer no greater than the captured page limit. Parse `qpdf --json=2 --json-stream-data=none --json-key=qpdf` output with a bounded 32 MiB output buffer and process timeout of 120 seconds. Output beyond that bound is an unsupported-PDF `pdf_malformed` rejection, not truncated data interpreted as clean. Require `qpdf[0].jsonversion=2`, traverse the object dictionary in `qpdf[1]` (including trailer and stream dictionaries), and reject `/OpenAction`, `/AA`, `/JS`, `/JavaScript`, `/Launch`, `/EmbeddedFiles`, `/EF`, `/Filespec`, `/AcroForm`, `/XFA`, `/RichMedia`, and action dictionaries whose `/S` is `/JavaScript`, `/Launch`, `/SubmitForm`, `/ImportData` or `/GoToR`. Also reject attached files and any unsupported/encrypted/object-parsing anomaly. This is a deliberately limited supported-PDF profile; every structural uncertainty is rejected or retried, never accepted. `clamdscan --fdpass --no-summary {private_path}` uses a locally configured Unix socket/daemon. Exit 0 is clean, 1 infected, 2/error/timeout unavailable. Capture tool output only in memory for classification and never log or return it. Hash exact validated bytes with streaming SHA-256 after scan, and verify size/hash again during promotion. Image-only pages are permitted; 008 evaluates text usefulness.

Fixed `reason_code` values are `upload_invalid`, `size_exceeded`, `not_pdf`, `pdf_malformed`, `pdf_encrypted`, `page_limit`, `active_content`, `malware_detected`, `inspection_unavailable`, `settings_unavailable`, `storage_unavailable`, `quarantine_expired`, `internal`. Do not expose signature, parser text or a scanner's malware name. A tool unavailable/timeout/error is `inspection_unavailable` and retryable; a determinate malformed/warning PDF is `pdf_malformed`, not retried.

## Attempt state machine and recovery

`receiving → quarantined → validating → promoting → accepted` is the normal path. `receiving|quarantined|validating|retry_pending|promoting → cleanup_pending → rejected|blocked` is terminal cleanup. `validating → retry_pending → validating` is a technical retry. `promoting → accepted` occurs only after ready Document verification. Terminal `accepted`, `rejected`, `blocked` cannot transition again. Every state write is compare-and-set under an attempt-row lock or affected-row predicate; job message duplication must be harmless. `reason_code` is null until rejection/retry, then an allowlisted code. `finished_at` exists only on terminal states.

Queue one validation job after staging transaction commit on dedicated `v3_intake` queue (`after_commit=true`, worker timeout 270 seconds, `retry_after=360`, job `tries=1`). `v3:reconcile-intake` runs each minute through Laravel scheduler and is safe concurrently with a job. It requeues quarantined/retry attempts due now, takes over a validating/promoting lease expired after 5 minutes, completes pending promotion, and purges cleanup. A duplicate job that cannot acquire the attempt claim exits without mutation. Scanner/tool/promotion-storage transient failure permits three additional 006 attempts after the first, delayed 60, 120 and 240 seconds. Increment `technical_failures` on each retryable failure; its values 1, 2 and 3 schedule those delays, and value 4 moves to cleanup/block. `scan_attempts` counts actual inspection claims; a pending-duplicate wait spends neither counter. The absolute quarantine deadline is 24 hours. 005 `technical_retries` and `retry_delay_seconds` belong to 007 workflow activities, not this pre-case gate. After budget/expiry: cleanup then `blocked`. Malware and deterministic PDF rejection: cleanup then `rejected`. Failed deletion remains `cleanup_pending`, is retried by reconciler every minute and cannot be served; after the 24-hour deadline emit only a fixed `cleanup_overdue` operational alert until deletion succeeds. `receiving` past its 24-hour `expires_at` with no complete staging is cleaned and blocked; do not race a slow live upload after five minutes. Reconciler checks DB-referenced paths and scans private quarantine/accepted prefixes for unreferenced files older than 24 hours; it deletes them. An accepted file is never removed by orphan cleanup. A missing or hash-mismatched accepted file blocks download/case use with `storage_unavailable` and is a safe operational error; it is not silently rebuilt from another owner's file.

## Document identity and promotion

`sha256` is lowercase SHA-256 of exact bytes and is server-internal. Unique `(owner_user_id,sha256)` is the serialization constraint, across ready and pending Documents. Different owners get separate Document rows and separate accepted paths even for identical bytes. An identical same-owner upload always retains its own attempt. If a ready Document exists, verify its stored file size/hash before linking, purge this attempt's quarantine bytes, then accept as duplicate. If the existing Document is `pending_move`, leave the new attempt `retry_pending` and reconcile; never overwrite its file. This pending-duplicate wait does not consume scanner technical retries. When the first Document becomes ready, verify it, link the waiting attempt and purge its staged copy. If the pending row is safely removed after failed promotion, verify the waiting staged file still matches its scanned size/hash and retry promotion before its 24-hour expiry. If the existing Document is corrupt/missing, block safely for operator repair; do not replace in place.

For a new hash, commit a `pending_move` Document and a `promoting` attempt in one DB transaction before moving bytes. Its accepted path is `accepted/{documentUUID}.pdf` on the same private disk. Atomically rename the quarantined file to that path; verify size/hash, then commit Document `ready`, `accepted_at` and attempt `accepted`, `document_id`, `finished_at`. On crash, reconciler uses the pending row: if destination exists and verifies, finish; if source exists and destination absent, retry rename; if neither verifies, remove any bad destination, delete the unreferenced pending Document under its lock, then cleanup/block the attempt. A failed DB commit after rename leaves a pending row, not a downloadable ready row. Do not count a pending Document as a prior duplicate available to teachers.

## Case request, ordering and errors

POST JSON contains exactly `{document_id: UUID,action:"process"|"process_again",idempotency_key: UUID}`; standard form fields map identically. Resolve current 004 role and owned Document before validating action/key to preserve missing/foreign 404 equivalence; check `ready` after visibility and return `document_not_ready` for an owned pending row. Parse `document_id` sufficiently to query it, then use strict controller-level validation; a FormRequest must not preempt resource visibility. If a matching owner/key case already exists, same Document/action returns it with 200 and original settings (even if current active settings changed); different Document/action is 409 `idempotency_conflict`. For a new key, `process` is allowed only with no previous case for that Document; otherwise 409 `duplicate_choice_required`. `process_again` requires a previous case; otherwise 409 `previous_case_required`. A teacher opens a previous case with GET, not a mutating `open_previous` action.

Use one write transaction. First-write 004's singleton access-lock revision and recheck active teacher; load the owned ready Document and lock it for case-start serialization; verify its private file still matches stored size/hash before a new case. Then inspect the idempotency key/prior-case condition, call 005 `SelectCaseSettings` on the same connection, verify the immutable version checksum and current byte/page limits against Document metadata, and insert the case. This lock order is **004 access singleton → owned Document → 005 settings pointer → case insert**; 005 publication uses access singleton then settings pointer. 006 never calls Temporal. Commit leaves state `awaiting_workflow`, `state_version=1`. Unique owner/key is the final duplicate guard. Race losers reread the winner only for a matching key; different first-process requests get the explicit 409. Retry serialization/unique conflicts with a bounded three-attempt transaction retry; if still unavailable return 503 without case. `process_again` with different keys intentionally creates distinct runs. A current-limit violation returns 409 `document_exceeds_current_limits` with no case.

| Condition | HTTP/code | Persistence |
|---|---|---|
| Guest / ineligible or wrong role | 004 401 `unauthenticated` / 403 `access_denied` | No intake mutation |
| Missing/foreign attempt, Document or Case | 404 `resource_unavailable` | No disclosure or mutation |
| Pending/unaccepted own Document | 409 `document_not_ready` | No case |
| Invalid upload/business input | 422 `upload_invalid` / `validation_error` | Attempt retained only if controller entered |
| Determinate PDF rejection | Poll state `rejected` with safe `reason_code`; asynchronous upload already returned 202 | No ready Document |
| Duplicate/action/key/current-limit conflict | 409 code named above | No new case |
| Missing/corrupt settings, DB/storage/worker unavailable | 503 `intake_unavailable` or `settings_unavailable` | No ready acceptance or new case |
| Missing/corrupt accepted bytes on download | 503 `storage_unavailable` | No byte response |

Custom errors use 004 shape `{error:{code,message}}`; attempt-bearing upload errors add top-level `attempt_id` only. Use a fixed generic message for each code. Invalid JSON fields use Laravel 422 field errors without reflecting input values. CSRF 419 retains framework behavior. Access denial auditing follows 004. 006 records safe attempt/case rows and fixed operational log codes; 015 later adds history without reading raw tool output. No admin PDF/intake list or download route exists.
