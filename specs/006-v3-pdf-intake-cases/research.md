# Research and Repository Evidence: 006

**Review date:** 2026-10-01. This records decisions from inspected repository files and primary tool documentation; no application integration was run.

| Decision | Evidence and rationale | Rejected alternative |
|---|---|---|
| Separate V3 private disk | `app/Http/Controllers/LectureController.php` stores legacy lecture PDFs on `public`; `config/filesystems.php` exposes the `public/storage` symlink and the local disk supports direct serving. Private `storage/app/v3`, `serve=false` and owner-authorized streaming prevent a V3 byte bypass. | Reuse public lecture path or signed storage URL |
| Separate upload attempt, Document and case IDs | Existing `lectures` migration/model does not encode quarantine, duplicate or multiple-run identity. A digest is byte identity, not a safe external identifier. Owner/hash uniqueness permits same-owner convergence without cross-owner disclosure. | Use `lecture_id`, filename or hash as case ID |
| qpdf 11+ JSON v2 as structural gate | [qpdf CLI documentation](https://qpdf.readthedocs.io/en/12.0/cli.html) defines `--is-encrypted`, `--check` exit statuses and JSON options; [JSON v2 reference](https://qpdf.readthedocs.io/en/stable/json.html) documents the two-element `qpdf` array: header/version then complete object dictionary. Therefore the adapter requests top-level `qpdf`, verifies JSON version 2, and inspects `qpdf[1]`. `--check` alone repairs or warns on some inputs and does not certify the supported active-content profile, so require clean exit and parsed-object rejection checks. Version/option mismatch is a fail-closed deployment gate. | Trust `%PDF-`, browser MIME, or `pdfinfo` alone |
| ClamAV daemon/client as malware gate | [ClamAV scanning documentation](https://docs.clamav.net/manual/Usage/Scanning.html) describes daemon/client scanning and local socket permissions; [protocol documentation](https://docs.clamav.net/manual/Usage/ClamdProtocol.html) distinguishes scan outcomes. The [clamdscan man page](https://manpages.ubuntu.com/manpages/trusty/man1/clamdscan.1.html) documents 0 clean, 1 infected, 2 error. Only 0 permits acceptance. A missing daemon is unavailable, not a clean scan. | Treat any process completion as clean or scan after case creation |
| Queue and scheduled recovery belong in 006 | `config/queue.php` defaults to database connection with `after_commit=false`; test environment uses sync. A 100 MiB upload plus parser and scanner can outlive HTTP. 007 Temporal is downstream and starts only after a case exists. 006 therefore uses an after-commit intake queue and scheduler for pre-case work. Its fixed three-retry pre-case policy is distinct from 005's `technical_retries`/`retry_delay_seconds`, which 005 assigns to 007 activities. | Require 007 workflow before a valid Document exists |
| Settings captured twice for distinct decisions | 005 [settings contract](../005-v3-versioned-settings/contracts/settings.md) gives byte/page limits and atomic `SelectCaseSettings`. Upload captures its active version before bytes; a later case must capture the current version and recheck limits so an older accepted file cannot bypass a tightened policy. Idempotent replay returns original case/version. | Copy active settings into rows, or silently reuse upload-time limits for new cases |
| 004 access first, then Document, then 005 pointer | 004 [access contract](../004-v3-access-ownership/contracts/access.md) requires current active actor and same-owner policy; 005 publication first-writes the 004 lock then the settings pointer. The same lock order avoids cross-feature lock inversions; a Document row lock serializes first-process choice. | Independent role check or unlocked check-then-insert |
| Retain minimal accepted evidence; purge unsafe bytes | 006 needs immutable owner/document/case lineage for 007–015. Rejected and expired quarantine bytes have no downstream purpose; accepted PDF must remain for 008 extraction/retry. 015 may add longer-term retention later. | Store scanner output/filename/admin content or delete accepted source before 008 |

The inspected environment has `pdfinfo`/`pdftotext`, but no `qpdf`, `clamdscan` or `clamscan` executable. Composer has no PDF-inspection or malware-scanning package. PHP tests use in-memory SQLite by default, which cannot prove independent-process race behavior. These are concrete provisioning/testing prerequisites, not reasons to omit the gates. `routes/v3.php` and V3 models/policies are not yet present because 004/005 are not implemented in this workspace. This plan consumes them when available and does not fabricate production placeholders.

The fixed business boundary remains: original teacher owns content and later review; admin has operational metadata only; 008 performs local extraction and NotebookLM `notebook_add_text`; 009 canonical prompts and all eleven First-step Section fields remain unchanged; JEV typed Choice/Score/Noul decisions and Temporal workflow belong to later specs. V2 materials are reference-only.
