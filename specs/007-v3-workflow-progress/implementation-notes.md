Create a dedicated after-commit `v3_workflow` queue and use a real worker/scheduler for live proof. Use deterministic `v3-case-{case_id}`, compare memo on adoption and never issue a new ID after a timeout. An open workflow without an available worker is delayed, not failed. Avoid a workflow-level retry policy that silently creates a new run.
- The initial real worker effect is a small signed Laravel callback activity. Laravel verifies the captured 005 row and includes only `technical_retries`, `retry_delay_seconds` and checksum in the signed start command; the activity uses that snapshot; `maximum_attempts` includes the first try. Its `event_key` makes uncertain HTTP delivery harmless. The SDK does not make later NotebookLM/JEV/coding external calls idempotent by itself; each later adapter must use a stable effect ID and reconcile its own ambiguous response.

Do those in activities or the bridge; pass only case/settings IDs and safe event codes through Temporal history. 007 parks at `wait_condition(lambda: False)` with no source handler or sender. 008 replaces that line in a replay-compatible rollout, deploys first, then sends an authorized `source_activation_v1` signal.
