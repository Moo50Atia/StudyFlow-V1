# 007 Foundations and Downstream Obligations

007 proves real start reconciliation, a safe Laravel case/event projection, captured-settings policy on its own callback activity and a synthetic-tested Temporal review gate. It does **not** prove that a PDF was extracted, NotebookLM mapped learning units, JEV qualified a prompt/scene, a candidate was checked, or the original teacher made an authorized review decision.

| Consumer | Required 007 surface | Consumer-owned integration and evidence |
|---|---|---|
| 008 extraction/source | One case workflow ID `v3-case-{case_id}`, captured settings ID, 006 verified `AcceptedPdfReader::openForCase`, safe milestone writer and an explicit parked workflow line | Add real local extraction/OCR and NotebookLM `notebook_add_text` through selected MCP adapter as Temporal activities or durable handoff. Use stable effect IDs and reconcile uncertain external calls; do not put PDF/text/notebook IDs in Temporal memo, admin DTO or ordinary callback. Deploy replay-compatible workflow code replacing 007's parking wait, persist/authorize a `source_activation_v1({case_id,activation_id})` request, then deliver it through an 008-owned authenticated path and verify it before external work; test an already-started 007 history resumes into live source work. |
| 009 learning map/Sections | Same case/settings identity and safe milestone channel | NotebookLM performs source-grounded Chapter/Mini Chapter/Lesson mapping. Preserve canonical dividing/execution/First/Second/Third prompts and all eleven First-step Section fields. Send only safe stage codes to 007; map/Section bodies stay in 009-owned storage. |
| 010 prompt/JEV | Captured 005 policy and 007 activity retry helper | Real prompt generation and direct typed JEV Choice/Score/Noul decision; classify typed policy failure versus transport/schema failure and make retries idempotent per prompt version. No second suitability model and no teacher prompt approval. |
| 011–012 scene/qualification | Case and qualified prompt lineage, safe stage callback | Register actual coding/check/JEV activities, stable candidate IDs, attempt/effect ledgers and stage-specific validators. Only 012's persisted overall pass may ask the workflow to enter the review gate. No raw HTML/check output in 007 event/admin DTO. |
| 013 teacher review | `ReviewGate` candidate/version/decision protocol; original 006 owner | Persist review decision and durable signal outbox in 013's transaction, recheck active original teacher and current qualified candidate, then deliver signal with same decision ID; query consumed ID/version to reconcile uncertain delivery. Teacher notes never enter Temporal signal/admin projection. 013 owns the real review route/record and approval/change consequences. |
| 014 admin operations | 004 closed DTO and safe case/event version | Extend read-only admin list with audited retry/hold/cancel commands; cannot send a teacher review signal or inspect content. An audited retry of 007 terminal case must define a new explicit policy without minting another workflow identity silently. |
| 015 history/evidence | Immutable 007 event sequence, safe timestamps/error codes and 006 settings lineage | Join private owner evidence and redacted admin metrics. Retain active/unresolved workflow links/events; do not treat zero pre-mapping scene count as an expected total or missing usage as zero cost. |

A later worker producer may emit only allowlisted operational milestone fields through the signed callback; its own feature must prove stage-specific preconditions and external-effect idempotency. Do not add a new teacher/admin session to the worker, expose a Temporal handle in a browser response, or use a V2/KOS/KIE production dependency. Temporal workflow-code changes must replay an existing 007 start history before rollout; tests should run an old-start/new-worker replay case. Future-feature test fixtures are never production services or models.
