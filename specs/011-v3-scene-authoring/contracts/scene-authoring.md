# Contract: 011 Scene Authoring v1

Read with [data model](../data-model.md), [acceptance matrix](acceptance-matrix.md), [005 settings](../../005-v3-versioned-settings/contracts/settings.md), [007 workflow](../../007-v3-workflow-progress/contracts/workflow.md) and [010 current-pass resolver](../../010-v3-prompt-jev-qualification/contracts/prompt-qualification.md). 011 produces **untrusted** candidates for [012](../../012-v3-scene-qualification/contracts/scene-qualification.md); it does not declare browser safety, JEV pass or review readiness.

## Input and provider wire

`author_initial(case_id,prompt_version_ref) -> candidate_ref | blocked | uncertain | stale`. Laravel `ClaimAuthoringRequest` calls 010's `QualifiedPromptResolver` under a case/Section-state lock; it never accepts a client `pass` flag. The current-pass signed GET remains the worker's private body read. The captured 005 settings version must match the case. `ApprovedTemplateRepository::getCaptured(scene.id,scene.checksum)` supplies exact UTF-8 system bytes. A missing/mismatched template or unsupported descriptor blocks before a send. The 011 user message is one UTF-8 JSON object with exactly `schema_version:1`, `prompt` (the exact 010 body), and `output_contract` (the exact constant below); Section ref is lineage only and no raw source/owner is sent. This fixed noncanonical output instruction is sent as user data, never appended to or substituted for the approved system template. No web/tool/code-execution capability, streaming, conversation memory or arbitrary settings URL. Use the fixed Gemini, Z.AI GLM and DeepSeek endpoints/auth/message roles and nonstreaming text extraction from 010's `FeedbackTextAdapter` contract; 011 has its own output parser, not its feedback revision policy. Each response must have exactly one complete nonempty text candidate and normal stop reason; record returned model and optional response ID. A filtered/truncated/multiple/tool-call response is known invalid output, never a second-model judgment. API/model access requires a live deployment check; no CLI provider appears in captured 005 settings.

`output_contract` exact UTF-8 value: `Return one JSON object only with schema_version 1 and a files array of path/content strings. Include a nonblank index.html. Other files may be local .js, .css, .svg or .json text. Use only relative local paths. Do not include remote URLs, build commands, Markdown fences or tool calls.` Do not add Section fields, source text, provider-specific instructions or a second prompt beyond these three JSON keys.

`ScenePackageV1` is exactly `{"schema_version":1,"files":[{"path":"index.html","content":"..."},...]}` with no other keys. It is a UTF-8 JSON object, not Markdown fences. Array length 1–32, unique case-sensitive **and case-folded** POSIX paths; each content is valid UTF-8 1–262144 bytes, total decoded content ≤1048576 bytes, response JSON ≤2097152 bytes. `index.html` is required, nonblank, begins with an HTML doctype or `<html` after leading whitespace, and is the only entrypoint. Additional extensions: `.js`, `.css`, `.svg`, `.json`; paths have 1–160 bytes, 1–4 segments of `[A-Za-z0-9._-]+`, no empty/`.`/`..` segment, leading dot, absolute path, backslash or colon. No symlink/hardlink/file-mode field exists. Files are text; no executable shell/build command or installer is accepted. All packaged dependencies must be local declared files; undeclared/runtime/external resource behavior is checked and blocked by 012's restricted browser, not certified by this collector. No V2 CDN is automatically allowed. A template incompatible with this contract is a deployment blocker until a newly approved template is registered through 005.

## Internal signed operations

All operations are on `routes/api.php` under 007's callback HMAC (`X-V3-*`), JSON only, no query string, verify signature **before** body parse or case lookup. UUIDs are lowercase canonical; strict unknown-key rejection. `GET` signs empty body. Success/error `Cache-Control: private, no-store`. Fixed errors `{error:{code,message}}`, messages generic. Unknown/foreign/stale refs use the same 404 `authoring_unavailable`; bad schema 422 `contract_invalid`; changed replay/state race 409 `authoring_conflict`; verified missing settings/private artifact 503 `authoring_unavailable`; bad HMAC 401 `worker_unauthenticated`. No raw prompt/template/code/provider response in errors/logs.

| Method/path | Exact request | Success and semantics |
|---|---|---|
| GET `/api/internal/v1/cases/{case_id}/scene-authoring/eligible-prompts` | empty | 200 `{data:[{section_ref,prompt_version_ref}]}` sorted by 009 Section ordinal; only 010 **current passing** versions in this case. Empty array is valid while work remains; no prompt bodies or old passes. Worker asks after each 010 qualification milestone and at final 010 completion, then idempotently claims each ref. |
| POST `/api/internal/v1/cases/{case_id}/scene-authoring/requests` | `{schema_version:1,prompt_version_ref:UUID}` | 201 or exact replay 200 `{data:{request_ref,section_ref,state,settings_version_id}}`. Key is `(case_id,prompt_version_ref,origin=initial)`. Under lock verify 010 current pass and captured template/order, persist request. |
| GET `/api/internal/v1/cases/{case_id}/scene-authoring/requests/{request_ref}/context` | empty | 200 `{data:{request_ref,section_ref,prompt_version_ref,qualification_ref,prompt,body_sha256,settings_version_id,settings_checksum,template_id,template_sha256,template_text,coding_order,coding_attempts}}`. Recheck 010 current pass and both private digests. Available only before/for the request's active attempt; stale returns 404 and the reconciler records `stale`. |
| POST `/api/internal/v1/cases/{case_id}/scene-authoring/requests/{request_ref}/attempts` | `{schema_version:1,ordinal:positive_integer}` | 201/200 exact ordinal replay `{data:{attempt_ref,ordinal,provider:{id,model,credential_ref},state:"send_reserved"}}`. | GET `/api/internal/v1/cases/{case_id}/scene-authoring/attempts/{attempt_ref}` | empty | 200 `{data:{attempt_ref,request_ref,ordinal,state,candidate_ref:null\|UUID,result_sha256:null\|sha256}}`; readback after lost acknowledgement. No raw content. |
| POST `/api/internal/v1/cases/{case_id}/scene-authoring/attempts/{attempt_ref}/result` | `AuthoringResultV1` below | 201/new or 200/exact replay `{data:{attempt_ref,state:"known_failure"\|"candidate_ready"\|"uncertain",candidate_ref:null\|UUID,result_sha256}}`. Candidate result is validated by Laravel, not trusted merely because worker parsed it. Changed digest 409. |

Only 012 internal worker receives bytes. Stale prompt returns 404. |

`AuthoringResultV1` exact keys: `{schema_version:1,outcome:"candidate"|"known_failure"|"uncertain",returned_model:null|string,provider_response_id:null|string,provider_response_json:null|object,package:null|ScenePackageV1,failure_code:null|"provider_unavailable"|"validation"|"timeout"|"internal",usage:null|{input_tokens:null|nonnegative_integer,output_tokens:null|nonnegative_integer,cost_minor_units:null|nonnegative_integer,currency:null|three_uppercase_letters},duration_ms:nonnegative_integer}`. Laravel computes `result_sha256 = SHA256(exact raw request body bytes)` **after signature verification and before parsing** and stores it with the first valid result; exact replay requires the same bytes and returns that digest. Whole request body ≤4194304 bytes, provider response JSON ≤2097152 bytes, non-null returned model 1–100 characters, response ID 1–255 characters, `duration_ms` 0–120000. A cost value requires a currency; absent cost has null currency. Candidate requires complete response/model/package and null failure; known failure requires a fixed failure code, null package, and may include retained response; uncertain requires null package and `timeout|internal`. Never send credentials. Provider response ID/model and raw JSON stay private. After reservation, a locally missing credential produces `known_failure/provider_unavailable` with no HTTP call and consumes that ordinal. The worker also posts a known failure for a definitive 401/403/429 refusal or complete unusable response; timeout, connection loss and 5xx after reservation are uncertain. A structurally valid completion with an invalid package/returned-model maps to a persisted `known_failure/validation` with the **same result digest**, no candidate and a success acknowledgement so fallback can proceed; malformed envelope is 422 without a result. A storage/DB failure after a valid result returns 503 and leaves the attempt uncertain until exact-byte result reconciliation. A POST timeout may be retried **with identical body** while the worker retains it; otherwise read status and stop, never call provider again automatically.

## Artifact, concurrency and state rules

The Laravel service writes normalized package files and a canonical `manifest.json` to staging on `v3_private`, each mode 0600, verifies hashes, then atomically renames into `scene-candidates/{case_id}/{candidate_ref}/`. Manifest exact keys: `schema_version:1,candidate_ref,request_ref,case_id,section_ref,prompt_version_ref,prompt_body_sha256,qualification_ref,settings_version_id,settings_checksum,template_id,template_sha256,attempt_ref,provider_id,requested_model,returned_model,entrypoint:"index.html",files:[{path,bytes,sha256}],created_at`. Sorted files, no credential/path/secret. Store `manifest_sha256` and relative private path in DB only after rename; candidate and request/attempt state commit in one transaction. The final directory cannot be overwritten; if DB commit fails, the unreferenced directory is quarantined and a same-attempt result reconciliation checks its digest before adoption or safe purge. Never delete a referenced or uncertain artifact automatically. 012's resolver rehashes bytes and refuses missing/corrupt artifacts.

Serialize request/attempt/result mutation with DB row locks and unique `(request_id,ordinal)`, `(request_id,provider_id)`, `(request_id,reserved_candidate_id)` constraints. Only one active `send_reserved|uncertain` attempt at a time; ordinal cannot skip. State: request `pending→authoring→candidate_ready|blocked|uncertain|stale`; attempt `send_reserved→candidate_ready|known_failure|uncertain`; `uncertain` may become a known result only on exact same retained response after reviewed reconciliation, not by a new provider send. `candidate_ready` is an immutable **collection** state; 012 stores independent check/qualification results. Before reserving or committing a candidate, recheck 010 current-pass identity; if changed, mark stale and keep any raw response private, no candidate. A superseded candidate already collected remains evidence but 012 resolver rejects it. Use a 60-second provider HTTP timeout and 30-second Laravel result timeout. Schedule `php artisan v3:reconcile-authoring` every minute: under a row lock, any `send_reserved` attempt older than five minutes becomes `uncertain` with its request; it never resends. The command also marks a request `stale` if its prompt was superseded and it has no live send; it retains earlier attempt evidence. A known result retained by the same worker may be replayed by digest; otherwise only 014 reviewed recovery may clear uncertainty. This also covers a crash between reservation and outbound send conservatively.

For each request, reserve providers at ordinals 1..`min(coding_attempts,coding_order.length)` **once each**. The remaining numeric budget is an upper bound, not permission to repeat a provider; 012 repair requests are new 012-owned operations. On all known failures, set Section request `blocked` with safe reason. Do not terminally fail the whole case while any current prompt can still be authored or any candidate can advance to 012. If 009 cursor is complete, 010 Section states terminal and all current passing Sections are blocked with zero candidate, emit proof-backed `workflow_failed/scene_generation/failed/provider_unavailable` via 007. `stage_started/scene_generation/running` requires a persisted request; `stage_completed/scene_generation/queued` requires a persisted candidate. Extend 007 projector with these exact evidence checks and deterministic event keys `scene:request:{request_ref}:started|candidate`; duplicate callback returns prior event, never a second count. No scene `pass` or review status is emitted.

## Owner/admin surface and recovery

`GET /v3/teacher/cases/{case}/scene-authoring` (`v3.teacher.cases.scene-authoring`) returns HTML or JSON `{data:{case_id,sections:[{section_ref,prompt_version_ref,state,candidate_ref:null|UUID}],updated_at}}`, ordered by 009 Section ordinal. Include each current 010 passing Section: if it has no request, project `pending`; otherwise use its stored request state. Status values `pending|authoring|candidate_ready|blocked|uncertain|stale`; no code, prompt, template, path, provider response or preview bytes. Use 004 active-original-teacher middleware/policy and owner-scoped query before lookup. Guest unauthenticated; inactive/other teacher/student/admin denied as 004 defines. Extend the existing 004 admin closed DTO counts with persisted 011 attempt/candidate counts only; no new admin content route. Existing V2 `SectionController`, `DynamicViewModel`, public storage and legacy teacher routes must never be linked to V3 candidate IDs. 011 creates no browser artifact delivery route.

Warnings use only `authoring_template_unavailable|authoring_provider_unavailable|authoring_attempt_uncertain|authoring_artifact_unavailable|authoring_replay_conflict` plus case/request/attempt refs and timestamp; no content. Deduplicate the same code per request for 24 hours. Retain attempts, requests, response evidence, template/prompt lineage and referenced files for pilot and while any attempt is uncertain. 015 may later define retention after active/uncertain references resolve. 014 may add audited reconciliation/retry, but 011 provides no admin action that reads code or unblocks an uncertain send.
