# 011 Foundations and Downstream Obligations

011 proves, **only after its own implementation, tests and live API gate pass**, that one current 010 passing prompt can yield a private immutable **untrusted** candidate. Its signed candidate resolver returns a rehashed manifest and files only while the prompt remains current. `candidate_ready` is collection status, not scene safety, JEV qualification, approval or teacher preview permission.

| Consumer | Use the 011 foundation | Consumer-owned implementation and proof |
|---|---|---|
| 012 scene checks/repair | Signed same-case candidate resolver, exact prompt/Section/settings/template/attempt lineage, immutable file bytes/digests | Execute only in restricted browser/container with blocked network and no app credentials; check controls/accessibility/runtime; apply direct typed JEV scene decision. Add its own repair-origin request/version extension and budgeted `limits.scene_repairs` path using 011's adapter/collector. A repair creates a **new** candidate; 011 initial-request schema does not fabricate a repair endpoint or candidate. 012 must recheck 010 current pass and candidate digest before every check/review handoff. |
| 013 teacher review | Only a 012 passing qualification paired with 011 candidate ID/version | Authorize active original teacher against case owner and current passing scene; supply isolated viewer, decision and private notes. Never treat 011 status or opaque candidate ref as review authority. |
| 014 operations | Request/attempt states, safe codes, reserved send IDs, response/candidate digests and uncertainty timestamps | Define audited, reviewed reconciliation of post-send unknowns and storage orphans; admin sees operational metadata, no prompt/HTML/template/response bytes. Never silently resend or replace a candidate. |
| 015 evidence/retention | Request→attempt→candidate immutable lineage and private manifest digests | Owner-authorized history may trace content refs; admin export remains closed metadata. Keep referenced and uncertain files until a policy can safely release them. |

No downstream consumer may infer authority from a UUID alone. Laravel remains the identity/owner/current-pass authority, while Temporal carries opaque refs/status only. V2 scenes/contracts are quality references and are not an implicit runtime dependency. KOS/KIE and multitenancy remain future work.
