# Data Model: 011 Scene Authoring

Create `database/migrations/2026_10_01_000011_create_v3_scene_authoring_tables.php` after 010. Use the configured Laravel relational connection (SQLite memory for routine tests; a real shared DB for the race test), `char(36)` server UUIDs, restrictive foreign keys and no copied owner column. Original owner is `v3_processing_cases.owner_user_id`. All cross-table case/Section/prompt/qualification/settings relationships are checked under a case/Section lock; single-column FKs do not prove the chain. Models use explicit table names and guarded lineage/state fields. Never use V2 `dynamic_views` or `sections`.

## `v3_authoring_requests` — `App\Models\V3\AuthoringRequest`

`id` UUID PK; `case_id` FK `v3_processing_cases.id`; `section_id` FK `v3_teacher_sections.id`; `prompt_version_id` FK `v3_scene_prompt_versions.id`; `qualification_id` FK `v3_prompt_qualifications.id`; `prompt_body_sha256`, `settings_checksum`, `template_sha256` `char(64)` non-null; `settings_version_id` unsigned bigint FK `v3_settings_versions.id`; `template_id` varchar(64) non-null; `origin` varchar(16) fixed `initial` in 011; `state` varchar(24) `pending|authoring|candidate_ready|blocked|uncertain|stale`; `state_version` unsigned bigint initially 1 and incremented on each state change; `attempt_limit` unsigned tinyint 1..3 equal to `min(coding_attempts, coding_order.length)`; `safe_error_code` nullable 004 allowlist; `last_alert_code` nullable varchar(32), `last_alerted_at` nullable; `created_at`,`updated_at`. Unique `(case_id,prompt_version_id,origin)`; 011 does not create repair-origin production rows. A request's lineage/captured bytes are immutable. Source lineage is transitive through the immutable Section→009 map→008 binding and case Document, checked rather than copied into a vendor request or admin DTO. Exactly one current request may author a given prompt version. `candidate_ready` requires exactly one committed candidate; stale request is never revived.

## `v3_coding_attempts` — `App\Models\V3\CodingAttempt`

`id` UUID PK; `request_id` FK; `case_id` FK; `ordinal` unsigned tinyint 1..3; `provider_id` `gemini_api|glm_api|deepseek_api`; `requested_model` varchar(100); `credential_ref` varchar(32) restricted 005 label, never secret; `state` `send_reserved|known_failure|candidate_ready|uncertain`; `reserved_candidate_id` nullable UUID fixed once before result staging; `result_sha256` nullable `char(64)` fixed on first result; `response_sha256` nullable `char(64)`; `response_path` nullable varchar(255) on `v3_private`; `returned_model` nullable varchar(100); `provider_response_id` nullable varchar(255); `failure_code` nullable 004 allowlist; `input_tokens`,`output_tokens`,`cost_minor_units` nullable unsigned bigint, `currency` nullable `char(3)`; `duration_ms` nullable unsigned bigint; `send_reserved_at`, `completed_at` nullable; `created_at`,`updated_at`. Unique `(request_id,ordinal)`, `(request_id,provider_id)`, `(request_id,reserved_candidate_id)` when non-null. No two active attempts for one request; lock its parent before insert. The committed reservation means a worker crash is **uncertain**, even if the network call may not have started. A known failure is append-only outcome evidence; its state is not reopened by normal workflow. `cost_minor_units` may be null because the vendor did not supply verifiable cost; never fabricate it from tokens.

## `v3_scene_candidates` — `App\Models\V3\SceneCandidate`

`id` UUID PK equal to attempt's `reserved_candidate_id`; `request_id` unique FK; `attempt_id` unique FK; `case_id` FK; `section_id` FK; `prompt_version_id` FK; `qualification_id` FK; `settings_version_id` FK; `manifest_path` varchar(255) on `v3_private`; `manifest_sha256` `char(64)`; `entrypoint` fixed `index.html`; `file_count` unsigned tinyint 1..32; `total_bytes` unsigned int 1..1048576; `collected_at`. No mutable `state`, `updated_at`, public URL, approval or preview field. Candidate existence means only 011 collection succeeded. 012 adds its own checks and qualification rows, 013 its own review decision. Immutable candidate file bytes and manifest are never overwritten; referenced and uncertain evidence is retained for pilot/015 rules.

## File/DB commit and recovery

`RecordAuthoringResult` locks request and attempt, verifies first `result_sha256`, assigns/persists `reserved_candidate_id`, writes private response evidence and normalized package to `scene-candidates/.staging/{case_id}/{attempt_id}`, fsyncs, hashes, renames exclusively to `scene-candidates/{case_id}/{reserved_candidate_id}`, then inserts candidate and changes attempt/request to `candidate_ready` in one DB transaction. Never hold a DB lock across provider HTTP. A storage failure leaves the attempt `uncertain` with reserved ID/digest; an unreferenced final/staging directory is retained for digest reconciliation, never presented to 012. On retry of the **same retained result bytes**, reconcile by comparing digest and file hashes, commit exactly one candidate or return the existing row. Changed replay is 409. 014 may review genuinely unknown sends; it cannot overwrite a prior candidate. `GET` for 012 rehashes manifest and all files before returning private bytes.
