# Data Model: 012 Scene Checks, JEV and Repair

Create `database/migrations/2026_10_01_000012_create_v3_scene_core_tables.php` for candidate state, check and JEV tables, then `database/migrations/2026_10_01_000012_create_v3_scene_repairs.php` for the repair table, both after 011 and lexically ordered as written. Use the existing Laravel relational connection; UUIDs are server-created `char(36)`, case/Section/prompt/candidate FKs restrict delete, and no editable owner column. Original owner is the 006 case. Verify the complete 009→010→011 same-case chain under a case/root lock; isolated FKs alone do not prove it. Guard lineage/state columns in models and register private read/owner policies; do not reuse V2 `DynamicViewModel`. SQLite memory is routine test DB, but true concurrency uses a shared transactional DB.

## `v3_scene_candidate_states` — `App\Models\V3\SceneCandidateState`

`candidate_id` UUID PK/FK `v3_scene_candidates.id`; `root_candidate_id` FK same table; `case_id`, `section_id`, `prompt_version_id` UUID FKs; `version_no` unsigned tinyint 1..11; `status` `awaiting_check|checking|check_failed|awaiting_jev|qualified|repair_pending|repairing|superseded|blocked|unavailable|stale`; nullable `check_run_id` FK, `qualification_id` FK (add after referenced tables), `safe_error_code` 004 allowlist, `last_alert_code` varchar(40), `last_alerted_at`; `state_version` unsigned bigint initially 1/incremented on transition; timestamps. Unique `(root_candidate_id,version_no)`. Initial candidate starts version 1 on claim; a linked `repair_N` candidate starts version N+1. `qualified` requires passing check and passing 012 qualification for that candidate; `superseded` requires a committed successor; neither state grants teacher review by itself. No copied teacher ID.

## `v3_scene_check_attempts` and `v3_scene_check_runs`

Attempt: `id` UUID PK; `candidate_id`, `case_id` FKs; `attempt_no` unsigned tinyint 1..11; `manifest_sha256`, `request_sha256`, `checker_version` non-null; `state` `claimed|technical_failure|recorded`; nullable `safe_error_code`, `result_sha256`, `started_at`, `lease_expires_at`, `finished_at`; timestamps; unique `(candidate_id,attempt_no)`. Max rows `technical_retries+1`; same candidate/checker/input digest across attempts. `lease_expires_at=created_at+90 seconds` using the DB clock; an expired claim is marked technical `timeout` in the next locked claim transaction, never a definitive result. A container launch/crash/OOM/timeout is technical, has no definitive check run and may retry without consuming repair budget.

Definitive run: `id` UUID PK; `candidate_id` unique FK; `winning_attempt_id` unique FK; `case_id`, `section_id`, `prompt_version_id` FKs; `settings_version_id` FK `v3_settings_versions.id`; `manifest_sha256`, `report_sha256`, `screenshot_sha256` `char(64)`; `report_path`, `screenshot_path` varchar(255) on `v3_private`; `checker_version` varchar(40) fixed `chromium-pw-1.63.0-v1`; `verdict` `pass|fail`; `failed_checks` JSON fixed code array; `duration_ms` unsigned int; `created_at`. A recorded run is immutable. A failed run has no JEV attempt. Browser report and screenshot are private, rehashed before evidence/repair/eligibility use.

## `v3_scene_jev_attempts` and `v3_scene_qualifications`

JEV attempt: `id` UUID PK; `candidate_id`, `check_run_id`, `case_id` FKs; `attempt_no` unsigned tinyint 1..11; `request_sha256`, `question_sha256`, `evidence_sha256` `char(64)`; `evidence_path` private varchar(255); `requested_model` varchar(100); `state` `claimed|technical_failure|recorded`; nullable `result_sha256`, `answer_sha256` char(64), `answer_path` private varchar(255), `safe_error_code`, `sent_at`, `lease_expires_at`, `finished_at`; timestamps; unique `(candidate_id,attempt_no)`. Max attempts `technical_retries+1`; all use identical state/question/model/settings and the same rehashed evidence artifact. `lease_expires_at=created_at+90 seconds` using the DB clock; an expired claim becomes technical `timeout` before the next ordinal claims, and its late result conflicts. Invalid typed responses retain their exact raw answer privately on the technical-failure attempt, with no qualification row. JEV read-only technical retry does not create a verdict. If evidence exceeds the 6 MiB contract or its exact artifact is missing, no attempt is sent.

Qualification: `id` UUID PK; `candidate_id` unique FK; `check_run_id` unique FK; `winning_jev_attempt_id` unique FK; `case_id`, `section_id`, `prompt_version_id` FKs; `settings_version_id` FK; `settings_checksum`, `manifest_sha256`, `evidence_sha256`, `request_sha256`, `question_sha256`, `answer_sha256` `char(64)`; `evidence_path`, `answer_path` private varchar(255); `rule_version` fixed `scene-rule-v1`; `requested_model`, `returned_model` varchar(100); `choice` `pass|revise|block`; `choice_confidence` decimal(20,18); `score` decimal(21,18); `score_confidence` decimal(20,18); `noul_probability` decimal(20,18); `noul_yes` boolean; `min_score`, `min_confidence` unsigned tinyint; `decision` `pass|revise|block`; `failed_checks` JSON fixed code array, including `repair_budget_exhausted` only when a valid nonpass has no slot; `created_at`. First valid typed answer is final; Laravel computes decision from captured numeric values without rounding, never from caller `pass`. A deterministic failure or unavailable JEV has **no** qualification row. A prior pass loses 013 eligibility when prompt/candidate chain tip changes, but remains historical evidence.

## `v3_scene_repairs` — `App\Models\V3\SceneRepair`

`id` UUID PK; `case_id`, `section_id`, `prompt_version_id` FKs; `root_candidate_id`, `from_candidate_id` FKs `v3_scene_candidates.id`; `to_candidate_id` nullable unique FK; `authoring_request_id` **nullable unique** FK `v3_authoring_requests.id`; `ordinal` unsigned tinyint 1..10; `criteria_path` varchar(255) on `v3_private`, `criteria_sha256` `char(64)`; `state` `claimed|authoring|candidate_ready|uncertain|blocked`; nullable `safe_error_code`, `last_alert_code`, `last_alerted_at`, `candidate_ready_at`; timestamps. Unique `(root_candidate_id,ordinal)` and `(from_candidate_id)` prevent fork. The nullable authoring FK breaks the creation cycle with 011: under one DB transaction and root lock, insert the repair row with null `authoring_request_id`, invoke an extended 011 `ClaimAuthoringRequest` with that repair ID (it validates the row, origin and copied lineage), set the request ID on the repair, and commit both. No committed repair may have a null authoring FK; rollback removes both on any error. Under the same lock, `ordinal=1+highest reserved ordinal`, `from_candidate_id` must be the current tip, and ordinal ≤ captured `scene_repairs`. The slot is reserved before 011 generation and never recycled automatically if authoring fails. At most the captured number of repaired candidates can exist; an unsuccessful slot has no invented candidate. 011 request origin is exactly `repair_{ordinal}` and existing `(case_id,prompt_version_id,origin)` uniqueness also guards duplicates. 012 extends 011's service validation for these origins only with a matching repair row; no 011 initial row or manifest is overwritten. The criteria artifact contains only fixed failed-check codes and bounded structural observations. 013 later owns any teacher-feedback-origin extension.

## Private write, concurrency and retention invariants

Paths: `scene-checks/{case_id}/{candidate_id}/{attempt_id}/{digest}.json` and `.png`, `scene-jev/{case_id}/{candidate_id}/{attempt_id}/{digest}.json`, `scene-repairs/{case_id}/{root_candidate_id}/{ordinal}/{digest}.json`, all on 008 `v3_private`. Stage with 0600 files, fsync, hash, exclusive rename, then DB transaction; never expose a row referencing missing/partial bytes. A DB rollback leaves an unreferenced file for same-digest reconciliation or later safe orphan cleanup, not a pass. Exact raw signed-result body SHA-256 fixes replay; changed replay 409. Lock candidate state and root before final decision/repair; DB unique constraints are the race backstop. Do not hold a DB transaction over Docker/JEV/API calls. A crash after an 011 repair candidate commits but before 012 link is reconciled by the same `authoring_request_id` and manifest hash; it cannot reserve a new repair slot. Preserve all referenced and uncertain rows/files for pilot and 015 retention rules. Logs/004 admin DTO/Temporal history contain only safe IDs, states and codes, never paths, screenshot, code, Section fields, prompt, answer or teacher notes.
