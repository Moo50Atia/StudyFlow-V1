# Contract: 012 Scene Qualification and Repair v1

Read with [data model](../data-model.md), [acceptance matrix](acceptance-matrix.md), [005 settings](../../005-v3-versioned-settings/contracts/settings.md), [007 workflow](../../007-v3-workflow-progress/contracts/workflow.md), [010 typed JEV rule](../../010-v3-prompt-jev-qualification/contracts/prompt-qualification.md) and [011 candidate/repair obligation](../../011-v3-scene-authoring/contracts/integration-obligations.md). 012 can prove an automated **qualification**, not visual perfection or original-teacher approval.

## Trusted input and state

`qualify(case_id,candidate_ref) -> qualified_ref | repair_ref | blocked | unavailable | stale`. Laravel resolves the 011 candidate through the signed current-candidate resolver, rehashes its manifest/files, checks the candidate's case/Section/prompt/settings chain and calls 010's current passing resolver. A candidate UUID, old 010 pass, caller-supplied check result or `candidate_ready` alone grants nothing. Repeat this check before a check claim, JEV claim/result, repair claim and 013 eligibility. 011's static package is local UTF-8 `index.html` plus declared `.js/.css/.svg/.json` files; 012 does not fetch V2 CDNs or install packages. A file/hash mismatch is `unavailable/internal`, not a repairable scene defect. Each candidate has at most one definitive check and one final qualification. Mutable Section status may point to the current chain tip; old candidate evidence stays immutable.

States for the candidate's 012 row: `awaiting_check→checking`; a definitive browser failure goes to `check_failed`, then `repair_pending` if budget remains or `blocked` with private `repair_budget_exhausted` reason and 004-safe `error_code:"validation"` if not. A browser pass goes to `awaiting_jev`. A valid JEV pass goes to `qualified`; a valid nonpass goes to `repair_pending` when repairable with budget, otherwise `blocked`. A reserved repair goes `repair_pending→repairing`; only a linked new candidate makes the predecessor `superseded`. A failed or uncertain authoring request leaves that predecessor `blocked` or `unavailable` respectively, without a successor. A technical browser/JEV fault goes to `unavailable` and has **no** scene verdict or repair-slot consumption. A recoverable unavailable candidate may reenter its same check/JEV stage only after the same underlying input/settings are reverified and under 007's bounded technical retry/014 reviewed operation; no new 011 coding send is inferred. `stale` is terminal for this candidate when 010's current prompt changes. A completed qualification record is append-only; a new repaired candidate gets new check/JEV rows.

## Real browser boundary and deterministic checks

Use a dedicated OCI checker image `v3_engine/qualification/Dockerfile` with Python 3.12, Playwright Python **1.63.0** and its matching Chromium. Run **one container per check attempt**, nonroot with Chromium sandbox enabled, `--network none`, private IPC/256 MiB shared memory, read-only root, no capabilities, `no-new-privileges`, user-namespace-capable seccomp profile, at most 1 GiB RAM/one CPU/128 PIDs and 60-second wall limit. Grant writable tmpfs only for the candidate and browser temp (combined ≤128 MiB). Pass the rehashed 011 package over stdin; mount no host path, Docker socket, app config, credential, source PDF or Laravel session. Only fixed locale/runtime variables enter the container. If the runtime cannot establish **all** of these controls or Chromium launches without its sandbox, return technical `unavailable`; never run on the host or loosen the controls. The checker emits capped JSON/PNG over stdout, not logs. The worker has no DB access and sends evidence to Laravel through 007 HMAC.

Inside that network namespace, a static server binds loopback `127.0.0.1:8765`, serves only declared paths and `index.html` with GET/HEAD and no listing, and supplies restrictive `default-src 'none'; script-src 'self' 'unsafe-inline'; style-src 'self' 'unsafe-inline'; img-src 'self' data: blob:; font-src 'self' data:; connect-src 'self'; object-src 'none'; frame-src 'none'; form-action 'none'; base-uri 'none'` CSP. Inline JS/CSS is permitted only because 011 allows a self-contained package; all network access still passes the exact path filter. Browser context has service workers blocked, no permissions, downloads disabled, popups closed and one page. Route every request: permit only exact loopback origin plus declared local path; abort and record any other `http(s)` or `file:` request, and close/record any WebSocket. `--network none` is the enforcement backstop even if interception misses an API. Browser navigation, redirects and local path traversal outside the declared set fail. No scene requests reach Laravel, metadata services or external hosts.

`CheckReportV1` has exactly `{schema_version:1,candidate_ref,manifest_sha256,checker_version:"chromium-pw-1.63.0-v1",checks:[{code,status,detail_codes}],observations:{dom_text,controls,resource_events,runtime_errors,asset_failures,console_error_count,page_error_count,forbidden_request_count},screenshot_sha256,started_at,finished_at}`. Exactly seven ordered check codes: `integrity,entrypoint,assets,runtime,network,interaction,accessibility`; `status=pass|fail`. `controls` contains at most eight `{ordinal,role,name,before_sha256,after_sha256,pointer_changed,keyboard_changed,focusable}` objects; `resource_events` at most 64 `{path,kind:"local"|"forbidden",status:"loaded"|"missing"|"blocked"}`; `runtime_errors` at most 16 `{kind:"console"|"page",source_file:null|declared_path,line:null|positive_integer,column:null|positive_integer,message}` with message ≤512 UTF-8 bytes; `asset_failures` is a unique sorted array of declared paths. Counts are nonnegative integers, timestamps ISO-8601 UTC and digests lowercase SHA-256. The versioned `resources/v3/scene/check-codes-v1.json` permits only `integrity_mismatch,entrypoint_missing,entrypoint_empty,asset_missing,asset_undeclared,script_error,console_error,forbidden_request,popup_attempt,download_attempt,interaction_absent,interaction_no_change,keyboard_inoperable,accessible_name_missing,document_lang_missing,document_title_missing,not_run_due_to_prior_failure`. No raw exception/prose is a code; browser message text stays private. `dom_text` ≤65536 UTF-8 bytes; if observation limits are exceeded, return technical `evidence_limit`, not a truncated passing report. Report JSON ≤262144 bytes; screenshot PNG 1280×720 at 1×, ≤2097152 bytes, private and separately hashed. Laravel validates PNG signature/dimensions and recomputes all digests. A checker infrastructure timeout/crash/OOM yields no definitive report and no JEV call. For a deterministic failure, record observed checks and use `not_run_due_to_prior_failure` on later checks rather than inventing a pass.

Minimum definitive pass: entrypoint parses into nonempty visible body; all requested declared local resources load successfully and no undeclared resource is requested; zero page errors/console errors; zero forbidden request/popup/download events; at least one visible semantic control (`button`, `input`, `select` or equivalent ARIA role) with a nonempty computed accessible name; at least one such control responds to pointer **and** keyboard input with an observable text/ARIA/value or canvas-pixel change. Compare action against an idle twin page at the same elapsed time so autoplay alone cannot satisfy interaction. Use up to eight controls in deterministic DOM order, fresh page per action, 500 ms stabilization, and canvas change threshold of >0.5% pixels beyond idle difference; DOM changes compare normalized text/ARIA/value hashes. Controls must be focusable through keyboard traversal. `html lang` and a nonempty document title are required. A missing interaction/accessibility feature is a repairable deterministic fail. A hostile outbound attempt is a repairable fail **inside this isolated checker**, never a reason to allow egress. A screenshot by itself is not interaction proof. 012's check does not replace 013's human visual review.

## Evidence and direct typed JEV rule

Only a deterministic pass enters JEV. `SceneEvidenceV1` is one private JSON object with exact keys `schema_version:1`, `candidate_ref`, `manifest_sha256`, `prompt_version_ref`, `prompt_body_sha256`, `section_fields` (all eleven verbatim 009 fields, including present empty `laws_if_any`), `prompt` (exact 010 body), `files` (all exact rehashed 011 path/content pairs), `check_report` (exact recorded text report, no screenshot bytes), and `coverage_matrix`. `section_fields` has exactly these keys in 009 order: `section_identity,core_understanding,visual_first_explanation,visual_scene_script,dynamic_view_blueprint,visual_learning_outcome,concept_check,conceptual_summary,colloquial_egyptian_explanation,laws_if_any,real_life_example`. The matrix has exactly one row per field in that order: `{field_name,expected_sha256,applicable,literal_evidence_refs,interaction_refs}`. `expected_sha256` hashes that field's exact stored UTF-8 bytes; `files` are sorted by 011 manifest path and each `content` is the exact private file text. Normalize NFKC/casefold and Unicode letter/number tokens of length ≥3 for **literal locator hints** in DOM/control labels/code; `laws_if_any` empty is `applicable:false`. A literal ref is only `dom_text`, `file:{declared_path}` or `control:{1..8}`, sorted and unique, when at least one normalized field token occurs in that evidence item. Interaction refs are all observed control IDs for `visual_scene_script`, `dynamic_view_blueprint` and `concept_check`; other rows have empty interaction refs. These hints do **not** assert semantic coverage or create a second model verdict. JEV receives the complete values and browser text evidence and judges the whole scene. Laravel builds/stores one fixed-key-order UTF-8 JSON byte string, hashes those exact bytes and serves the same bytes to each technical JEV attempt. No silent truncation/summarization; serialized state ≤6291456 bytes, otherwise technical `evidence_limit` and no JEV call. Browser screenshot stays private for later human inspection; JEV v1 sees **textual** evidence, not pixels.

Use 010's fixed TypeSafe `POST /v1/systemone` transport, `JEV_MODEL`, Bearer credential, `GET /v1/models` live gate and typed wire parser. Add shared exact question asset `resources/v3/jev/scene-questions-v1.json`, with named questions `choice`, `score`, `noul` sent together, no fourth judge:

- Choice criteria: `pass` = exact prompt/Section goals and observed controls are supported by code/browser text with no contradiction; `revise` = correctable omitted/weak concept, example, function or interaction; `block` = irreconcilable source contradiction, unrelated scene or intentional unsafe behavior. Instruction: `Classify this scene against the qualified prompt, Section fields, code and textual browser evidence; do not claim to inspect screenshot pixels.`
- Score instruction: `Rate source fidelity, required concept/example/function/interaction coverage, observed operation and learning clarity on the requested 0–100 levels.` Its 101 ordered strings are `n/100: ` plus band: 0–19 `contradictory or nonfunctional scene`; 20–39 `major source or interaction gaps`; 40–59 `partial scene with weak execution evidence`; 60–79 `working grounded scene with notable gaps`; 80–100 `working grounded scene with strong textual evidence`. Never rescale afterward.
- Noul instruction: `Do the supplied code and textual browser observations support this scene's alignment with the exact qualified prompt and Section requirements?`; true = `The supplied textual evidence supports alignment`, false = `Evidence is absent or contradicts alignment`.

Require exactly those named matching typed answers and finite in-range Choice confidence, Score 0–100/confidence and Noul probability as in 010's adapter. A successful typed answer is applied **directly**: pass iff `Choice=pass`, `Score≥qualification.scene.min_score`, `100×Choice.confidence≥min_confidence`, `100×Score.confidence≥min_confidence`, `Noul≥0.5`, and `100×Noul≥min_confidence`, all inclusive on unrounded values. Noul probability is the confidence in a **yes** answer per owner correction. Persist returned/requested model, three typed values, question/request/answer digests, thresholds and failed-check codes `choice|score|choice_confidence|score_confidence|noul|noul_confidence|repair_budget_exhausted`. Choice=`block` is terminal even if another threshold passes. A different valid nonpass is `revise` while a repair slot remains; when none remains, decision is `block` with private `repair_budget_exhausted` appended to the failed-check list while original typed Choice remains unchanged; owner/admin status exposes only 004-safe `error_code:"validation"`. Malformed/missing wire or transport error has **no verdict** and uses technical retry only; never send a successful response to another model for usability approval.

## Signed operations, replay and recovery

All new internal routes live in `routes/api.php` behind 007 callback HMAC: method, exact path, timestamp and raw body digest; verify signature before JSON parse/lookup. No query strings. All POSTs reject missing/extra keys. Case path must match every child row. Same-case missing/foreign/stale IDs use 404 `{error:{code:"scene_unavailable",message:"Scene unavailable"}}`; malformed schema 422 `contract_invalid`; changed replay/concurrent stale version 409 `scene_conflict`; verified missing private bytes/runtime 503 `scene_unavailable`; bad HMAC 401 `worker_unauthenticated`. All responses `Cache-Control: private, no-store`; no content/error detail in logs. Server hashes exact raw POST body for idempotent result replay and independently recomputes all rule outcomes.

A first claim returns `send_now` exactly once per attempt; duplicate claimed calls return `reconcile`, not another send. Each claim has a DB-clock lease expiring 90 seconds after creation; browser and JEV worker operations have a 60-second hard timeout. When a lease expires without a result, the next claim transaction records that attempt as `technical_failure/timeout` and permits only `attempt_no+1` under the captured cap. A result arriving after expiry or after a successor claim is 409 and cannot replace a later result. Exact committed result replay still returns the prior result. Browser attempts may retry after a technical crash because they have no external network and write no application state until signed result commit; each attempt has a fixed `(candidate_id,attempt_no)` ledger, max `technical_retries+1`. JEV is read-only and may technically retry the same evidence digest; a valid recorded typed answer is final. The check request digest is SHA-256 of UTF-8 `012-check-v1\n` plus candidate UUID, manifest SHA, checker version and captured settings checksum separated by LF. The JEV request digest is SHA-256 of `012-jev-v1\n` plus candidate UUID, manifest SHA, report SHA, exact evidence SHA, question SHA, captured settings checksum and requested model separated by LF. Laravel computes both from stored data; no caller digest grants authority. No DB transaction spans browser/JEV calls. A 503/timeout posting a **known** result may replay identical raw body after safe status readback; lost result bytes remain `unavailable`, never fabricated. Private report/PNG/answer writes use staging, fsync, exclusive rename, hash and transaction; orphan files are retained until digest reconciliation and only unreferenced, nonuncertain files older than 24 hours can be removed. A stale prompt during a call prevents result/repair/eligibility commit but preserves private attempt evidence.

## Repair authoring extension and user boundary

012 extends 011's guarded `v3_authoring_requests.origin` values from `initial` to `repair_1`…`repair_10`, using existing unique `(case_id,prompt_version_id,origin)`; no initial row is changed. Under one Laravel transaction/root lock, 012 inserts a repair row with null authoring FK, then invokes an extended 011 `ClaimAuthoringRequest` with the repair ID; 011 validates that row and copies the failed candidate request's exact prompt/qualification/settings/template IDs/digests into a new same-case/Section request. 012 links its request ID before commit; no null-linked repair may commit. Any failure rolls back both rows and does not consume an ordinal. Extend 011's attempt/context/result services only for a repair request proved by that row; its existing `coding_order`, one-provider-per-ordinal limit, immutable `ScenePackageV1` collector and uncertainty rules still apply. `RepairCriteriaV1` is fixed-key-order UTF-8 JSON `{schema_version:1,failed_candidate_ref,failed_gate:"browser"|"jev",failed_checks:[fixed_codes],check_observations}`. For browser failure, `failed_checks` is the unique ordered nonpass `detail_codes` from the seven check rows, excluding `not_run_due_to_prior_failure`; for JEV nonpass, it is the stored 012 qualification failed-check array. `check_observations` is copied from the definitive report in both cases. Hash these exact criteria bytes as `criteria_sha256` before inserting the repair row. The Python authoring activity sends the exact 011 `schema_version,prompt,output_contract` JSON plus one `repair` object `{previous_candidate_ref,files:[{path,content}],criteria_sha256,failed_gate,failed_checks:[fixed_codes],check_observations}`. `files` are rehashed 011 bytes; `check_observations` is exactly `{asset_failures,runtime_errors,forbidden_request_count,control_roles:[string]}` derived from the failed private report, with ≤32768 serialized bytes; no raw Section fields, JEV prose, source PDF, owner or credential. Same approved scene system-template bytes are used. A repair output is a **new** 011 candidate; the 012 repair row supplies predecessor/version lineage without editing 011's exact manifest. A known failed/uncertain repair authoring request has no successor and cannot silently allocate another ordinal. `limits.scene_repairs=0` permits no repair. Choice=`block`, stale prompt and infrastructure outage do not claim an automatic repair slot. 013 may later extend this service for a committed teacher visual request; 012 creates no review-decision placeholder.

`GET /v3/teacher/cases/{case}/scene-qualification` (`v3.teacher.cases.scene-qualification`) returns HTML or JSON `{data:{case_id,sections:[{section_ref,candidate_ref,candidate_version,status,error_code}],updated_at}}`, sorted by 009 Section ordinal and containing only Sections with a 011 candidate. Status is `awaiting_check|checking|check_failed|awaiting_jev|qualified|repair_pending|repairing|blocked|unavailable|stale`; no content, score, provider, private path, screenshot or note. Use 004 active-original-teacher middleware/policy and owner-scoped case lookup before child lookup; foreign/missing same 404. Map the DTO `error_code` only to 004's safe allowlist: null for `awaiting_check|checking|awaiting_jev|qualified|repair_pending|repairing`; `validation` for `check_failed`, deterministic/JEV `blocked` or `stale`; `timeout` for an exhausted timed-out attempt; `provider_unavailable` for JEV service refusal/outage; `internal` for checker/runtime, private-artifact or evidence-limit faults. Never expose private failed-check or browser detail codes in this DTO. No browser scene or 012 evidence route is exposed to teacher/admin. V2 `/sections`, `/lectures`, legacy study-flow and `/storage` must not resolve V3 candidate IDs. Admin remains on 004's closed case DTO, with only safe `scene_qualification` stage/status/error; 012 does not change `approved_scene_count`.

Emit 007 `stage_started/scene_qualification/running` key `scene:check:{candidate_ref}:started` only after same-case check claim; emit `stage_completed/scene_qualification/queued` key `scene:qualification:{candidate_ref}:passed` only after current final pass. The 007 projector must verify row/current-chain proof, workflow identity and fixed event/status/error values. A per-Section block/repair does not terminally fail the case while another current Section can continue. Only after 009 cursor complete, all 010 Sections terminal, all current passing Sections' 012 chains terminal blocked and no candidate eligible/pending/unavailable may a proof-backed `workflow_failed/scene_qualification/failed/validation` event key `scene:qualification:all_blocked` fire. 012 emits no `teacher_review`, `awaiting_review`, approval or review signal; 013 owns that producer.

Warn only fixed `scene_checker_unavailable`, `scene_jev_unavailable`, `scene_artifact_missing`, `scene_repair_uncertain`, `scene_evidence_corrupt`, at most once per condition per candidate/24 hours, with case/candidate/check/attempt IDs and no content. Keep all referenced and unresolved private evidence for pilot; 015 later defines deletion. 014 may add audited recovery without admin content access. Every internal/browser/owner response is `private, no-store`; 004 denial audit remains authoritative for user-route denials.
