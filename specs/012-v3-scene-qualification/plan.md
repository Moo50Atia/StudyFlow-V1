## Ordered implementation decisions

1. Claim a rehashed **current** 011 candidate and 010 passing prompt under Laravel case/root lock. No content/body enters Temporal. Add immutable check/attempt evidence and state tables; no teacher preview route. Recheck before every result/repair/eligibility commit.
2. Build the checker as a dedicated Playwright 1.63.0 Chromium container with nonroot sandbox, seccomp, no egress, no host mount/secret, fixed resources and wall limit. The worker passes candidate bytes by stdin and receives capped report/PNG by stdout. Within the container, serve only declared local files and enforce CSP/browser routing. Actual container tests, including an outside listener and hostile candidate, must prove the boundary; a mocked browser cannot.
3. Persist one definitive `CheckReportV1` pass/fail with private screenshot after independent Laravel validation. A deterministic fail gets no JEV call; a container failure consumes only a 007 technical retry. Build `SceneEvidenceV1` with all eleven Section fields, exact prompt/files and textual browser report. The 11-row matrix contains **locator hints**, not a new semantic verdict. If complete evidence exceeds 6 MiB, stop with technical `evidence_limit` rather than silently reducing source requirements.
4. Use 010's vendor transport/parser with fixed 012 question asset. Laravel recomputes the exact 005 scene rule from typed Choice/Score/Noul, including Noul probability as yes confidence. No extra suitability judge. Only both gates pass for 013 eligibility; JEV outage is not a low score.
5. For deterministic or correctable JEV failure, lock root, reserve a unique `repair_N` slot within captured 005 budget and extend 011's request/adapter/collector for repair context. Same prompt/settings/template, full previous package and fixed criteria; new immutable candidate links through `v3_scene_repairs` and restarts both gates. A terminal Choice block, stale prompt or technical outage cannot trigger automatic repair. 013 may later add teacher-requested visual repair without a production placeholder here.
6. Add evidence-guarded `scene_qualification` milestones and owner-safe status. 013 reads only the current passing eligibility resolver and must implement its own owner decision/viewer. Admin remains on 004 closed DTO. Verify duplicate/concurrent claims, lost acknowledgements, file/DB faults, V2/public bypass and workflow replay.

## Runtime and evidence gates

The official [Playwright Python Docker guidance](https://playwright.dev/python/docs/docker) says its image includes browser dependencies but not the Python package, root disables Chromium sandbox, and nonroot plus seccomp is needed for untrusted pages. Pin the image/package to 1.63.0 and test sandbox startup with the exact restrictive launch policy; do **not** use `--ipc=host` or `--cap-add=SYS_ADMIN` in this content boundary even if a development example suggests them. The documented [network router](https://playwright.dev/python/docs/network) and [service-worker block](https://playwright.dev/python/docs/service-workers) support observation, but `--network none` is the egress boundary. A safe deployment must have an OCI runtime that enforces these controls; no host-browser fallback. Live gate also calls the case-selected JEV model from 010 and persists actual typed response evidence. A fake JEV fixture and mocked container cannot prove either live gate. Stop on missing runtime, compatible candidate, complete evidence, selected model or protected secret configuration rather than weakening the checks.
