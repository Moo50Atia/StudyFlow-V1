# 009 Handoff to Prompt Qualification and Later Features

009 proves a source-scoped NotebookLM map, coverage record, immutable work order and complete First-step teacher Sections for the first work item. It supplies a cursor/completion/Continue mechanism tested with a **test-only** 010 receipt. It does not prove that 010 produced Third outputs, a full multi-Lesson three-step loop, JEV qualification, scenes or teacher review.

| Consumer | 009 surface | Consumer obligation |
|---|---|---|
| 010 prompt/JEV | Signed `GET /api/internal/v1/cases/{case_id}/lesson-context/{work_ordinal}` gives current map/work/Section refs, private conversation ref and five canonical digests to the trusted worker; signed completion receipt/009 cursor gate. `v3_lesson_queries` holds any combined `Continue` raw reply privately. | Execute the unchanged Execution, Second and Third bodies, with transport metadata defining the canonical completion marker's X as 009's work ordinal (including a promoted Mini Chapter). Persist each Section's Second/Third result and final conversation ID before calling 009 completion, using one opaque Third ref per exact current Section ID. If a literal `Continue` reply contains all three steps, parse/reuse its Second/Third output rather than blindly sending the same step again. Prove live multi-Lesson continuation, not only 009's fixture. Apply typed JEV Choice/Score/Noul directly under 005 policy; no extra successful-response judge. |
| 011–013 scene/review | Immutable `TeacherSection.id` and case/map/work lineage | Preserve original owner and Section identity into prompts/scenes. No admin access to Section/answer bodies; original teacher alone reviews the final scene. |
| 014 operations | 004 closed case DTO and 009 safe `mapping` stage/error codes | Define audited operator handling for an uncertain sent `Continue`; do not resubmit it merely because no answer was recorded. |
| 015 evidence | Map/query/Section/cursor IDs, digests, private answer artifacts and accepted/uncertain timestamps | Retain/derive owner-only evidence; exclude map titles, Sections, prompts, answers and provider/conversation IDs from admin exports. Do not purge unresolved queries. |

The current 010 plan says it invokes Second and Third and then asks 009 to advance. That is compatible for the first work item, but a subsequent literal `Continue` may already return a complete three-step answer under the canonical Execution protocol. Before 010 implementation, its own spec/plan must define whether to consume that recorded combined reply or use a provider-supported staged turn, and test the choice live. 009 cannot safely decide from a fake response or edit 010 here. Until 010 supplies durable Third evidence and this continuation behavior is verified, the 009 production cursor remains at `awaiting_010` and a full multi-Lesson completion claim is unavailable.
