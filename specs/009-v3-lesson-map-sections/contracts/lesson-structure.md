## Immutable prompts and query grammar

[Canonical prompt text](canonical-prompts.md) is an input artifact, never an editable settings template. The SHA-256 of the UTF-8 text **inside** each fenced block, excluding the fence and its delimiter newline, is: Divide `77620579df1bb2fb51876116b1266a32fe58ecd963486c3d76d5c98c46d012ff`; Execution `5ab2448f34c9b2b90199347772d10d7d217ba9fd468dffc28e3169bd0a7fdce9`; First `04450e9fd7e0962ceb4f60a1f641e43b671d7be2622718e202af0ca92683b788`; Second `a8776affc821a1b913a4685b309dc0304afc03c7389fcfe44b366b6f5683f203`; Third `07798d744b973ec11248897d2efe0e769ab481c4a21cce7562696dd131217955`. CI compares runtime assets to this file byte-for-byte; no whitespace/spelling correction. This is a checksum of the checked-in owner-provided text, not evidence that NotebookLM followed it.

008's `KnowledgeSourceAdapter.query` retries queries under captured technical policy, which is unsafe for stateful `Continue`. 009 extends the same adapter with `query_once(case_id,binding_ref,query_text,conversation_ref?)`, preserving 008's case/source-ID checks and ≤16,384 UTF-8 query-byte limit but making **one** MCP `notebook_query` send after Laravel commits the query claim. No internal transport retry after send; timeout is uncertain. The selected tool expects `{notebook_id,query,source_ids:[bound_source_id],conversation_id?}` and returns `{answer,conversation_id}`. Inspect installed `tools/list` and live round trip before relying on this schema. A missing/empty conversation ID is a nonaccepted response, never replaced with a guessed ID. Query input/output stays activity-local until the raw answer is posted to Laravel; it never becomes a Temporal activity result.

The Divide request is exactly the Divide body, with no additional model instruction. Parse only nonempty lines matching optional `-`/`*` bullet, label `Chapter`, `Mini Chapter` or `Lesson` (case-insensitive ASCII), optional decimal/Roman number, delimiter `:`/`-`/`=>`, then a 1–255-character title. Reject prose, code fences, repeated numbering within the same parent, orphan Mini/Lesson, Lesson under Lesson, empty Chapter and empty map. An unnumbered line gets its ordinal from source order; titles may repeat. Direct Lesson under Chapter and Lesson under Mini are valid. A Mini with no Lesson is promoted to a work item. Assign depth-first `W1..Wn` only after the full parse; these IDs are map-local ordinals, not provider IDs. Do not infer units from PDF headings locally.

Coverage request is a separate, fixed 009 query in the Divide conversation, not a rewrite of the canonical Divide body. It begins `COVERAGE CHECK v1\nFor every literal [PAGE i/N] source marker, assign the educational content on that page to one or more listed work items. Return exactly one line PAGE i: Wn[,Wn...] for each i=1..N; use PAGE i: GAP when no assignment is grounded. Output no other text.\nWORK ITEMS\n` followed by `Wn | <full Chapter / Mini Chapter / Lesson path>\n` in work order. If this complete request exceeds 008's 16,384 UTF-8-byte query cap, block with `validation`/`map_too_large` before a coverage send; never truncate paths or ask about only some work items. Parse exactly N lines with page integers 1..N once, known W IDs only, no GAP, at least one page per W; overlapping page assignments are allowed. The page count comes from the bound 008 extraction, not the provider. Store query/answer and sorted page arrays. This mechanical check plus known-fixture live assertions detects gaps but cannot establish that every fact on a page was mapped; do not claim semantic exhaustiveness.

The first work item query is `TARGET WORK ITEM v1\nW1 | <full map path>\nTreat only this mapped work item as the single Lecture. In your output write exactly Lecture: W1 | <full map path>. Do not include any other work item.\nCANONICAL FIRST BODY\n` followed by the exact First block. The prefix is 009 transport scope metadata; do not edit the canonical block. The parser requires the exact `Lecture: W1 | ...` header, `Section 1:` through `Section N:` with contiguous positive ordinals, and the eleven First labels in their canonical order under each Section. A label ends with `:`; multiline value continues to the next known label/Section. Reject repeated/missing labels, unrecognized field labels that look like headings, empty Sections, other work-item headers or text that merges fields. Preserve value text after LF normalization; trim only for nonempty validation. `القوانين (إن وُجدت)` may have an explicitly present empty value; all other fields require nonempty text. The displayed colloquial label includes the canonical leading `•`. One response may have multiple Sections. Size cap and raw-answer retention follow [data model](../data-model.md).

## Activation and Temporal handoff

`php artisan v3:dispatch-maps` runs each minute for 007 cases with `stage_code=sourcing,status_code=queued`, an 008 `bound` binding and a currently open fixed workflow. Lock case/link/binding, create one `v3_map_activations` row, and enqueue an after-commit 007 `v3_workflow` job. The 007/008 worker must deploy a replay-compatible 009 signal handler **before** the scheduler is enabled. Laravel signs `POST /internal/v1/workflows/{workflow_id}/activate-map` with 007's bridge HMAC and exact JSON `{schema_version:1,case_id,binding_ref,activation_id}`. Bridge describes the fixed workflow, verifies 007 memo case/settings and signals `mapping_activation_v1` with this payload. 202 acknowledges signal delivery only. A lost acknowledgement leaves the same activation ID `uncertain`; minute reconciliation re-signs and resends that ID only. The workflow accepts first matching case/binding/activation, ignores exact duplicate and refuses a different ID/binding; its activity revalidates the Laravel row and 008 bound state before querying. A closed/mismatched workflow is 409 `mapping_activation_conflict`; Temporal outage is 503 `workflow_unavailable`; an unresolved signal alerts once per 24 hours with safe code `mapping_activation_overdue`.

The 009 workflow schedules map/coverage/First activities with only `{case_id,activation_id,binding_ref,work_ordinal}` and receives only safe refs/status/version. It emits `stage_started/mapping/running`, then `stage_completed/mapping/queued` after the first work item's Sections are committed, using 007's signed event key/version replay rules. Extend 007 `ProjectCaseEvent` with a provenance-checked `map_blocked` event for a current 009 activation/map/query: `stage_code=mapping,status_code=blocked,error_code=validation` for deterministic malformed map/coverage/First response; verified missing private answer/settings uses `internal`, pre-send provider outage after captured retries uses `provider_unavailable`. An uncertain sent query stays running/delayed, never falsely blocked or completed. Exact keys are `map:started`, `map:completed`, `map:blocked`. The workflow then waits without occupying an activity worker for a 010 completion signal; 009 does not create prompt/JEV/scene events.

## Signed Laravel worker operations

All Python→Laravel operations extend 007 HMAC-only `routes/api.php` and verify signature/timestamp/contract version **before** body parsing or ID lookup. Sign method, exact path, timestamp and raw-body digest per 007; no query string. All success/error responses use `Cache-Control: private, no-store`. JSON errors are `{error:{code,message}}`: 401 `worker_unauthenticated` / `Worker authentication failed.`, 404 `lesson_unavailable` / `Lesson is unavailable.` for unknown/foreign/stale refs, 409 `lesson_conflict` / `Lesson state changed.`, 422 `lesson_invalid` / `Lesson request is invalid.`, 503 `lesson_unavailable` / `Lesson is unavailable.` for DB/private-disk outage. No raw answer, prompt or provider error appears in an error or ordinary log.

Laravel computes query `request_sha256 = sha256("009-query-v1\n" + case_id + "\n" + binding_ref + "\n" + map_ref + "\n" + kind + "\n" + decimal_ordinal + "\n" + decimal_utf8_byte_length(conversation_in_or_empty) + ":" + conversation_in_or_empty + "\n" + sha256(query_text_utf8))` and answer SHA-256 itself. `parsed` is exactly one of `{nodes:[{kind,position_path,parent_position_path:null|string,title,ordinal_in_parent,work_ordinal:null|integer}]}` for Divide, `{pages:[{page,work_ordinals:[integer]}]}` for coverage, or `{work_ordinal,lecture_header,sections:[{ordinal,fields:{section_identity,core_understanding,visual_first_explanation,visual_scene_script,dynamic_view_blueprint,visual_learning_outcome,concept_check,conceptual_summary,colloquial_egyptian_explanation,laws_if_any,real_life_example}}],completion_marker:null|integer}` for First/Continue. Laravel validates exact keys/types, recomputes parent/ordinal/coverage/field invariants and requires parsed titles/field values to match their normalized raw-answer spans; it does not blindly accept a worker-provided JSON summary. A ready map cursor takes the coverage query's `conversation_out` as its first conversation ID. For a known answer Laravel stores raw bytes privately, then commits query/map/nodes/Sections/cursor in one DB transaction under case lock; a DB failure leaves a purgeable orphan, never an accepted cursor without an answer. Query `prepared→sending|blocked`, `sending→recorded|uncertain|blocked`, `uncertain→recorded|blocked` only when the exact same response is available; `send_count≤1` under DB constraint and locked service guard. A lost provider response after claim stays `uncertain`, since MCP has no proven query idempotency or conversation-history read. A missing conversation ID blocks acceptance. Duplicates with same answer/conversation return committed refs; a changed answer for the same query is 409. Do not re-query to repair an unknown result automatically.

The completion digest is `sha256("009-completion-v1\n" + case_id + "\n" + map_ref + "\n" + decimal_work_ordinal + "\n" + decimal_expected_cursor_version + "\n" + comma_join(section_refs_in_ordinal_order) + "\n" + comma_join(third_output_refs_in_matching_order) + "\n" + decimal_utf8_byte_length(final_conversation_ref) + ":" + final_conversation_ref + "\n" + completion_ref)`. Laravel verifies the supplied lowercase digest; `section_refs` and `third_output_refs` arrays must be in matching Section ordinal order. This is an authenticated 010 attestation of persistence, not independent 009 verification of 010's future tables.

On a successful completion receipt Laravel dispatches `NotifyLessonCompletionJob` after commit. It signs `POST /internal/v1/workflows/{workflow_id}/lesson-ready` with 007's bridge key and exact JSON `{schema_version:1,case_id,map_ref,work_ordinal,cursor_version,completion_ref}`. Bridge verifies the fixed workflow/memo and signals `lesson_ready_v1` with that body. 202 means the signal was accepted, not that Continue ran. Duplicate same `(case_id,cursor_version,completion_ref)` is a no-op; a different ref/version for the same work item is 409 `lesson_conflict`. A lost acknowledgement retries only the same signal; the minute reconciler checks `ready_to_continue|complete` rows lacking a recorded signal acknowledgement. The workflow handler rechecks Laravel's committed cursor/version before Continue. A final-work `complete` signal parks for later features without another query or marking the overall case approved/complete.

## Continuation, teacher views and privacy

After a full 010 completion receipt, the cursor becomes `ready_to_continue` for nonfinal work or `complete` for the last work item. Only the nonfinal phase claims `continue` for the **next** ordinal. Its query text is exactly `Continue`, with the attested final conversation ID. The provider response must identify the expected next work item by the canonical execution completion marker's X ordinal and yield complete First fields for that next item; 009 stores the entire raw response, parses only First Sections, and atomically moves the cursor. 010 owns any Second/Third material in that combined response and must not repeat a provider step blindly. If the provider returns no usable identity/First fields, `continue_uncertain` retains the old ordinal and raw response for investigation. A final cursor sends no Continue. Neither a browser nor an admin can issue Continue.

Append `GET /v3/teacher/cases/{case}/lesson-map` named `v3.teacher.cases.lesson-map` and `GET /v3/teacher/cases/{case}/sections/{section}` named `v3.teacher.cases.sections.show` to 004 `routes/v3.php`, behind actual active original-owner middleware.
