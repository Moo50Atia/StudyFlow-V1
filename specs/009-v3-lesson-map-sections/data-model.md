# Data Model: 009 Map, Query Evidence, Sections and Cursor

All UUIDs are server generated, all case FKs reference 006 `v3_processing_cases.id` with restricted delete, and the original owner is resolved through that case. Do not copy an editable owner ID onto a map or Section. Use the 006/008 private `v3_private` disk for answer artifacts; provider conversation IDs and answer paths never appear in 004 admin projection or Temporal payloads. These tables are 009-owned and do not alter V2 `lectures`/`sections`.

## `v3_map_activations` — `App\Models\V3\MapActivation`

`id` UUID PK; `case_id` UUID unique FK; `binding_id` UUID FK `v3_knowledge_source_bindings.id`; `workflow_id` varchar(64) fixed to `v3-case-{case_id}`; `state` enum string `pending|signaling|uncertain|accepted|blocked`; `signal_attempts` unsigned int default 0; nullable `lease_until`, `signal_attempted_at`, `signal_accepted_at`, `next_check_at`, `last_alerted_at`; nullable safe `error_code`, `last_alert_code` varchar(32); timestamps. The one-per-case row fixes the signal ID/binding. Only the same ID may be resent after a two-minute lease; `accepted` cannot regress. Case and 008 binding must be `bound` and still match the current 007 link before every signal.

## `v3_lesson_maps` — `App\Models\V3\LessonMap`

`id` UUID PK; `case_id` UUID unique FK; `binding_id` UUID unique FK; `activation_id` UUID unique FK; `state` `pending|ready|blocked`; `divide_query_id`, `coverage_query_id` nullable UUID FKs to `v3_lesson_queries.id` (add after both tables exist); `divide_prompt_sha256`, `coverage_prompt_sha256`, `map_sha256` nullable char(64); `page_count` unsigned int from 008 extraction; `work_count` unsigned int default 0; nullable safe `error_code`; timestamps. `ready` requires both recorded query artifacts, an accepted map digest, one or more work nodes, all pages 1..N covered and each work node assigned at least one page. Once ready, hierarchy/binding/prompt digests are immutable. An exact replay returns its ID; a divergent replay conflicts. No partial map becomes current.

## `v3_lesson_nodes` — `App\Models\V3\LessonNode`

`id` UUID PK; `map_id` UUID FK restrict; nullable `parent_id` UUID self FK restrict; `kind` `chapter|mini_chapter|lesson`; `position_path` varchar(64) unique within map, e.g. `001.002.003`; `ordinal_in_parent` unsigned int ≥1; `title` varchar(255), nonempty UTF-8; nullable `work_ordinal` unsigned int ≥1; nullable `coverage_pages` JSON (sorted distinct integers). Unique `(map_id,position_path)` and `(map_id,work_ordinal)`; work ordinals form 1..`work_count` in depth-first source order. `lesson` is always a work item. A `mini_chapter` becomes a work item only when it has no Lesson children. `chapter` is never a work item. Duplicate titles are allowed; ID/path and parent distinguish them. Validate same-map parent and acyclic allowed nesting in service, not by title.

## `v3_lesson_queries` — `App\Models\V3\LessonQuery`

`id` UUID PK; `case_id`, `map_id` UUID FKs restrict; `kind` `divide|coverage|first|continue`; `target_work_ordinal` unsigned int (`0` for divide/coverage, actual work ordinal for first/continue); unique `(case_id,kind,target_work_ordinal)`; `state` `prepared|sending|uncertain|recorded|blocked`; `send_count` unsigned int default 0 with maximum 1; `request_sha256` char(64); nullable `canonical_prompt_sha256` char(64) (required for Divide/First, null for coverage/Continue); nullable private `conversation_in`, `conversation_out` varchar(255); nullable `answer_path` varchar(255), `answer_sha256` char(64), `answer_bytes` unsigned bigint, `sent_at`, `recorded_at`, `last_alerted_at`; nullable safe `error_code`, `last_alert_code` varchar(32); timestamps. The request hash covers exact query bytes, case/binding/map/target and conversation input; it is computed server-side. Claim `sending`, `send_count=1` and `sent_at` in Laravel before calling `notebook_query` through 009's 008-adapter `query_once` extension. A crash after claim is `uncertain`; no automatic resend. A known response is written atomically to `lesson-answers/{case_id}/{query_id}/{digest}.txt` before `recorded`; read verifies digest. Maximum answer size is 4 MiB; larger answers block with safe `validation`, digest/byte count evidence and no accepted map/Sections. An orphan private file older than 24 hours is purged only if no row references it. An unreferenced provider conversation is not automatically adopted.

## `v3_teacher_sections` — `App\Models\V3\TeacherSection`

`id` UUID PK; `case_id` UUID FK; `map_id`, `work_node_id`, `query_id` UUID FKs restrict; `ordinal_in_work` unsigned int ≥1; unique `(work_node_id,ordinal_in_work)`; `section_identity`, `core_understanding`, `visual_first_explanation`, `visual_scene_script`, `dynamic_view_blueprint`, `visual_learning_outcome`, `concept_check`, `conceptual_summary`, `colloquial_egyptian_explanation`, `laws_if_any`, `real_life_example` each non-null long text; `first_prompt_sha256` char(64), `answer_sha256` char(64); timestamps. Each value is stored verbatim after LF normalization, without merging/summarizing or silent translation. All fields must be present and nonempty after trimming except `laws_if_any`, which may be an explicitly present empty value. The fixed display labels, including `• شرح للجزء بالعامية المصرية`, come from the immutable First block; DB column names are internal. Same-case/map/work/query parent checks are transactional. No per-Section owner mutation, soft delete or admin serializer.

## `v3_lesson_cursors` — `App\Models\V3\LessonCursor`

`case_id` UUID PK/FK; `map_id` UUID unique FK; `current_work_ordinal` unsigned int ≥1; `phase` `first_pending|awaiting_010|ready_to_continue|continue_uncertain|complete|blocked`; `conversation_id` nullable private varchar(255); nullable `last_query_id`, `last_completion_id` UUID FKs, safe `error_code`; `version` unsigned int ≥1; timestamps. Create only with a ready map. First acceptance sets `awaiting_010` without advancing. A signed 010 completion receipt for the current ordinal, complete current Section ID set, nonempty opaque Third-output refs and final conversation ID creates the immutable completion row below and changes phase to `ready_to_continue` (or `complete` on the last item); 009 records **attested** completion, while 010 must prove its own output persistence. Continue claim changes `ready_to_continue→continue_uncertain` before provider call; only a verified next answer plus complete First Sections atomically increments ordinal, updates conversation/version and sets `awaiting_010`. Duplicate same completion/answer returns the committed result; changed or stale expected version is 409. `complete` is terminal and sends no Continue. `blocked` denotes deterministic map/First validation failure; `continue_uncertain` is recoverable only by explicit reviewed reconciliation, never a guessed resend.

## `v3_lesson_completions` — `App\Models\V3\LessonCompletion`

`id` UUID PK; `case_id`, `map_id`, `work_node_id` UUID FKs restrict; `work_ordinal` unsigned int; unique `(case_id,work_ordinal)` and `(case_id,completion_ref)`; `section_refs` JSON nonempty exact ordered current Section IDs; `third_output_refs` JSON same count of nonempty opaque refs; `completion_ref` varchar(255), `completion_sha256` char(64), `final_conversation_id` private varchar(255); `signal_state` `committed|signaling|uncertain|accepted`; `signal_attempts` unsigned int default 0; nullable `lease_until`, `signal_attempted_at`, `signal_accepted_at`; timestamps. The signed 010 receipt is retained per work item, not overwritten on cursor advancement. Commit completion/cursor together and dispatch `NotifyLessonCompletionJob` after commit; a lost bridge acknowledgement resends only this row's fixed signal. A duplicate exact receipt returns this row; a changed ref/Section set/conversation conflicts. An accepted signal is not proof that a subsequent Continue ran.

Keep maps/nodes/queries/Sections/cursor and unresolved evidence for the pilot while the case exists. 015 later defines expiry; 009 adds no delete/export route. A referenced missing/hash-mismatched answer artifact fails closed with `internal`, never reparses from a provider reply or advances the cursor.
