# Contract: 013 Original-Teacher Review v1

Read with [model](../data-model.md), [cases](acceptance-matrix.md), [004 access](../../004-v3-access-ownership/contracts/access.md), [007 ReviewGate](../../007-v3-workflow-progress/contracts/workflow.md), [010 correction base](../../010-v3-prompt-jev-qualification/contracts/prompt-qualification.md) and [012 eligibility/repair](../../012-v3-scene-qualification/contracts/scene-qualification.md). Laravel, not a candidate URL or Temporal signal, is the authority for original ownership and current review state.

## Review creation, state and dormancy

`EnsureReviewReady(case_id,candidate_ref) -> review_ref | unavailable`: under case/Section/review-state locks, resolve 012's current `review-eligible` proof with the same DB lineage, rehash 011 package and current 010 prompt, and insert one item bound to `{case_id,section_ref,candidate_ref,candidate_version,prompt_version_ref,qualification_ref}`. Unique candidate and current Section pointer make duplicate 012 completions/scheduler scans return the same pending item. A decided item on a still-current approval remains readable but is never recreated or made pending. After a change request or post-approval correction starts routing, the same old qualified candidate cannot be requeued; only a **new** qualified candidate may create the next item. If the 012 current tip changes, atomically stale that Section's old pending item and clear any approval pointer for the former tip, preserving its historical approval; the new tip starts `pending/awaiting_review`, `ready_at` from the DB clock. `php artisan v3:reconcile-scene-reviews` runs each minute to find passing tips missed by a workflow callback. It cannot create an item for failed, unavailable, older-tip or foreign candidate. The worker can call the signed ensure route below and list current opaque items; no teacher content enters Temporal.

A pending item becomes `dormant` when DB time reaches `ready_at + captured limits.review_dormancy_days`; run `php artisan v3:mark-dormant-reviews` daily. Opening it records a private `last_opened_at` observation but never resets `ready_at` or auto-approves; the owner workspace continues to show the pending action. Admin sees only 004-safe `teacher_review/awaiting_review` state and a dormant count (if 014 later exposes it). An inactive teacher keeps the item; 004 denies access until restoration or 014 cancellation. No other teacher/admin receives it. A final decision changes the item to `decided` and clears the current review pointer. A review item cannot be revived after it is `stale` or `decided`.

## Owner HTTP interface

Append only these routes to 004's `routes/v3.php` under its actual active-original-teacher middleware/policy, web session, CSRF for mutations and `private, no-store` for **every** success, error, PNG and middleware denial. Resolve the owned case before nested Section/review/approval/session lookup. Guest JSON 401 `unauthenticated`; inactive, wrong-role or student 403 `access_denied`; missing/foreign parent or child indistinguishable 404 `resource_unavailable`; invalid body 422 `contract_invalid`; stale version/current proof or changed idempotency replay 409 `review_conflict`; storage/viewer/bridge unavailable 503 `review_unavailable`. Browser flows use 004 login/denial, validation redirect, generic 409/503 and normal 419 CSRF. Fixed JSON errors are `{error:{code,message}}` with no content or private IDs. Reject unexpected business keys; `_token`/`_method` are framework fields only.

`PreviewActionV1` is exactly `{schema_version:1,expected_frame_no:nonnegative_integer,kind,payload}`. `kind=click` has `payload:{x:integer 0..1279,y:integer 0..719}`; `kind=press` has `payload:{key:"Tab"|"Shift+Tab"|"Enter"|"Space"|"Escape"|"ArrowUp"|"ArrowDown"|"ArrowLeft"|"ArrowRight"|"Backspace"|"Delete"}`; `kind=type` has `payload:{text:UTF8_string 1..256 bytes}`. Maximum request 1024 bytes. One action advances `frame_no` by one under the viewer-session lock; exact action replay returns the same frame, changed replay/old expected frame is 409. The UI exposes these actions through keyboard-accessible controls and an input, not a canvas-only pointer interface.

`ReviewDecisionV1` is exactly `{schema_version:1,idempotency_key:UUID,expected_review_version:positive_integer,candidate_ref:UUID,candidate_version:positive_integer,decision:"approve"|"request_changes",feedback_kind:null|"visual_interaction"|"factual_source"|"mixed",notes:null|UTF8_string}`. `approve` requires null kind/notes and a successful owner-authorized GET of frame 0 for this exact item/candidate; bridge start or viewer metadata alone is insufficient. `request_changes` requires a selected kind and nonblank LF-normalized notes of 1..8192 UTF-8 bytes; it may be submitted without a successful preview, because a teacher can describe a scene problem, but a technical preview outage by itself never automatically consumes a repair slot. Preserve exact normalized bytes; treat notes as untrusted data in provider calls. `mixed` routes to prompt requalification. No model infers a category, and there is no “ambiguous” auto-route.

For decisions and post-approval corrections, authenticate/authorize **before** idempotency lookup. Preview start/frame/action accepts a pending/dormant item or a decided approved item **only while** its approval is Section-current; a stale/historical review cannot start a viewer session. Hash fixed-key-order UTF-8 JSON of the validated fields after LF note normalization (excluding framework CSRF fields) and store that digest as `request_sha256` on the immutable source row; same case/key/canonical body returns the committed result (after current actor eligibility), changed same-key body returns 409. A different key for an already decided/stale review or an old approval returns 409. In one case/Section/review transaction: reload original owner and current 012 proof, compare expected versions and current pointer, stage/rehash note if any, insert immutable source/route/outbox/audit, update Section pointer/state, and insert a proof-backed 007 case event. An audit/outbox/DB failure rolls back all rows and no signal is sent. Never hold a transaction across a provider, container or Temporal call. A successful HTTP response means the decision is durable; delivery may still be pending and is visible only as safe status. A stale candidate cannot be approved even if a prior preview succeeded. A committed decision or post-approval correction closes the source review's preview sessions; kill containers after commit, and if the kill acknowledgement is lost the worker lifetime cap still applies while owner frame/action routes deny the closed sessions. A current approval may open a **new** owner session for later inspection.

## Interactive preview trust boundary

013 extends the 012 Playwright 1.63.0 checker image with `v3_engine/review/preview_entry.py` and a private single-process `preview_gateway.py`. The Laravel owner controller resolves/re-hashes the exact 011 package and sends its bytes to the 007 private bridge using the existing HMAC method/path/timestamp/raw-body-digest scheme. The gateway starts **one container per viewer session** through stdin/stdout with 012's nonroot Chromium sandbox, `--network none`, read-only root, no capabilities/host mount/Docker socket/app secret, bounded tmpfs, 1 GiB/one CPU/128 PIDs, and a 30-minute absolute lifetime/15-minute idle kill. One preview service replica/worker holds process handles for the pilot, maximum eight concurrent sessions; a restart marks sessions unavailable and reaps labeled orphan containers before accepting new sessions. If it cannot enforce the exact controls, return 503 and show no scene. The container static server serves only declared local files on loopback; Playwright blocks service workers, popups/downloads, external requests and redirects as in 012. Candidate bytes and browser code never enter a teacher browser, Laravel HTML response, public disk or Temporal history.

The gateway accepts only signed internal start/action/frame/close calls from Laravel using 007 bridge HMAC, stores only ephemeral process state and returns `PreviewFrameV1={viewer_ref,frame_no,png_base64,dom_text,controls,runtime_error_count,forbidden_request_count}`. Exact private bridge operations are: `POST /internal/v1/review-preview/sessions` with `{schema_version:1,viewer_ref,candidate_ref,manifest_sha256,files:[{path,content}]}` (≤2 MiB) returns 201/200 `{data:{viewer_ref,frame_no:0,frame:PreviewFrameV1}}`; `POST /internal/v1/review-preview/sessions/{viewer_ref}/actions` with the same `PreviewActionV1` returns the next `PreviewFrameV1`; `GET /internal/v1/review-preview/sessions/{viewer_ref}/frames/{frame_no}` returns that exact frame; `DELETE /internal/v1/review-preview/sessions/{viewer_ref}` returns 204. Same start ref plus same manifest is idempotent, changed package 409; session missing/expired 404, policy/container failure 503, bad HMAC 401 before lookup. Python rejects any undeclared file/path and never accepts an arbitrary URL, host path or credential. Laravel rechecks owner/current review for **every** outward frame/action and validates the signed bridge response; record `first_frame_at` only after the owner-authorized outward GET of frame 0 succeeds, never at bridge start, viewer metadata GET or action. Validate PNG signature/dimensions/≤2 MiB and bounded escaped text/controls in Laravel; a scene attempt to navigate or call out is blocked and recorded. Do not proxy arbitrary URL or let candidate code choose a bridge path. The owner page's CSP permits its own UI JS and same-origin PNG/JSON only; `frame-src 'none'`, `object-src 'none'`, and no scene iframe. A screenshot plus remote pointer/keyboard actions shows the actual running scene, while the accompanying semantic controls allow keyboard review. The [HTML standard](https://html.spec.whatwg.org/multipage/iframe-embed-object.html) warns against combining script and same-origin sandbox permissions on a same-origin frame; this design avoids that browser-side boundary entirely. A mock gateway proves UI logic, not isolation; R08/R26 require the real container and an outbound host-listener test.

## Durable Temporal handoff and multi-Section completion

Extend 007's `CaseWorkflow` with a `ReviewGate` instance per Section, keyed by Section ref, not one gate for the whole case. A qualified-tip activity calls the signed ensure route and `enter(candidate_ref,candidate_version)`; a periodic 60-second durable timer plus the Laravel reconciliation command discovers missed items. The new signed private bridge `POST /internal/v1/workflows/{workflow_id}/review-decisions` accepts exactly `{schema_version:1,case_id,section_ref,review_ref,decision_ref,candidate_ref,candidate_version,outcome:"approve"|"request_changes"}`. It signals `review_decision_v1`; the gate ignores different candidate/version, changed reused decision ID or stale Section. If a signal arrives before `enter`, buffer only the one exact pending tuple for that Section until the matching gate exists. `GET /internal/v1/workflows/{workflow_id}/review-decisions/{decision_ref}` queries whether that exact decision was consumed. Laravel's `v3:dispatch-review-effects` scheduled each minute first queries, then resends the same ID/payload if needed; timeout stays `uncertain`, no second decision. On approval the workflow continues siblings; on request changes it fetches the opaque route and drives the proper correction path. No review note, prompt, HTML, frame, owner identity or private path enters the signal/history.

For **every** post-approval correction, whether the original case workflow is open or closed, the committed correction/outbox starts `CorrectionWorkflow` with deterministic ID `v3-review-correction-{correction_ref}` and reject-duplicate reuse policy through new signed bridge `POST /internal/v1/workflows/review-corrections`; `GET /internal/v1/workflows/review-corrections/{workflow_id}` describes the fixed ID. The input is exactly `{schema_version:1,case_id,section_ref,correction_ref,route_ref,settings_version_id,settings_checksum}`. A timeout is uncertain; describe/adopt matching memo before retry, never launch a new ID for the same correction. It runs the same visual/factual route then 012/ReviewGate on the new candidate. The original closed run is not restarted. Both workflows use 007's durable task queue and no workflow-level retry; activity effects are claimed/reconciled by Laravel ledgers.

013 extends 007's trusted Laravel event projector only for persisted review proofs: `review:{review_ref}:ready` → `teacher_review/awaiting_review`; `review:{decision_ref}:changes` → `teacher_review/running`; `review:{decision_ref}:approved` → `teacher_review/awaiting_review` while another Section is pending, or `complete/approved` only when the 009 cursor is complete and **every expected current Section** has an active approval for its current 012-qualified tip, with no pending/routing/unavailable Section; `review:{correction_ref}:reopened` is the sole proof-backed `complete/approved→teacher_review/running` transition. Only when every expected Section is terminal approved or blocked, at least one current route is blocked, and none is pending/running/unavailable may proof event `review:all_blocked` set `teacher_review/blocked/validation`; this is not a false `complete/approved`. An uncertain provider/Temporal effect leaves safe running/delayed state for 014 recovery, never terminal success. No 013 route publishes a scene to students or modifies V2 content.

## Privacy and recovery

Store notes and provider outputs on `v3_private` with exact digest and atomic write; no note body in a review/outbox/Temporal/admin DTO. A failed DB/audit write rolls back and no signal is sent. A lost decision HTTP response is resolved by same-key replay; a lost Temporal response is resolved by the gate query or fixed workflow describe, never by creating another decision/effect. An unavailable preview leaves review pending and disables approval, without an automatic repair slot. A lost preview gateway process closes ephemeral sessions and is restartable from the same immutable candidate; it cannot alter the decision. Retain referenced/uncertain evidence for pilot and 015; 014 may later add audited reminders, cancellation and recovery without teacher-content access. Test real V2 `/sections`, `/lectures`, `/api/lectures`, `/teacher-study-flow` and `/storage` paths as well as new owner routes; none may resolve a V3 candidate/note by UUID. Admin remains on 004's closed DTO and receives only safe status/count/error, never prompt, fields, PNG, code, note or hash.
