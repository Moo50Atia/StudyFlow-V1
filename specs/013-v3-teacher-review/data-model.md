# Data Model: 013 Review, Correction and Delivery

Use Laravel's existing relational connection and 008 `v3_private`. Create `database/migrations/2026_10_01_000013_create_v3_review_core.php` (Section pointer, item, decision, approval, route, outbox, preview session and post-approval correction tables), then `2026_10_01_000013_extend_v3_scene_review_repairs.php` (narrow 012 teacher-route FK/criteria extension), then `2026_10_01_000013_extend_v3_prompt_teacher_corrections.php` (013 prompt-effect table and 010 origin/FK extension). Create UUIDs server-side as `char(36)`; all case/Section/candidate/qualification/prompt FKs restrict deletion. Validate the full same-case lineage under a case/Section lock; independent FKs are insufficient. Original owner comes from the immutable 006 case, not an editable review owner column. A Section can have many historical candidates/reviews/approvals but one current review or approval pointer. SQLite memory is routine testing only; two-process races need a shared transactional DB.

## `v3_review_section_states` — `ReviewSectionState`

`section_id` UUID PK/FK `v3_teacher_sections.id`; `case_id` UUID FK; nullable `current_review_item_id` FK, `current_approval_id` FK (add after referenced tables); `state` `awaiting_qualification|awaiting_review|routing|approved|blocked|unavailable`; `state_version` unsigned bigint initially 1, incremented on every transition; nullable 004-safe `error_code`; timestamps. At most one of the two current pointers is nonnull. `approved` requires a current approval pointing to the same Section and a currently passing 012 candidate; `awaiting_review` requires a current pending/dormant item. A committed change request, post-approval correction or newly qualified 012 current tip clears the former current approval pointer without deleting its historical approval. Lock this row with case/Section state and enforce pointer invariants in the transition service.

## `v3_teacher_review_items` and `v3_teacher_review_decisions`

Item: `id` UUID PK; `case_id`, `section_id`, `candidate_id`, `qualification_id`, `prompt_version_id` FKs; `candidate_version` unsigned tinyint 1..11; `status` `pending|dormant|decided|stale`; `state_version` unsigned bigint initially 1; `ready_at`, nullable `dormant_at`, `last_opened_at`, `decided_at`; timestamps; unique `candidate_id` and `(section_id,candidate_id)`. The sole creation path verifies 012's current eligibility tuple and stores those exact refs/version. An item never changes candidate or qualification. A stale former item stays historical and cannot be decided.

Decision: `id` UUID PK; `review_item_id` unique FK; `case_id`, `section_id`, `candidate_id`, `qualification_id` FKs; `actor_user_id` FK `users.id` (audit identity, not transferable owner); `candidate_version`, `expected_review_version` positive integers; `idempotency_key` UUID, `request_sha256` char(64) of the contract's canonical validated body; `decision` `approve|request_changes`; nullable `feedback_kind` `visual_interaction|factual_source|mixed`; nullable `note_path` varchar(255) on `v3_private`, `note_sha256` char(64), `note_bytes` unsigned integer 1..8192; `created_at`; unique `(case_id,idempotency_key)`. Approve has null feedback/note fields; request changes has all three populated. Notes are LF-normalized exact UTF-8 and nonblank after trim; they are never an admin, Temporal or normal-log column. Decision rows are immutable. The active original teacher is reloaded at submit, even for exact replay.

## `v3_approved_scenes` and `v3_postapproval_corrections`

Approval: `id` UUID PK; `case_id`, `section_id`, `candidate_id`, `qualification_id` FKs; `review_decision_id` unique FK; `candidate_version` unsigned tinyint; `approved_at`; unique `candidate_id`. This row is immutable historical evidence. The Section state's current pointer, not row existence, determines current approval and `approved_scene_count`; a correction clears the pointer but retains this row.

Post-approval correction: `id` UUID PK; `case_id`, `section_id`, `approval_id` unique FK; `actor_user_id` FK; `idempotency_key` UUID unique within case, `request_sha256` char(64) of the contract's canonical validated body; `feedback_kind` `visual_interaction|factual_source|mixed`; `note_path`, `note_sha256`, `note_bytes` as above; `state` `accepted|routing|uncertain|blocked|completed`; `created_at`; unique `(case_id,idempotency_key)`. It can be created only while that approval is current. It uses the same owner/category/note rules as a review change request and starts a new version; the old approval remains historical. A closed original `v3-case-{case_id}` run is never restarted.

## `v3_review_routes` and `v3_review_outbox`

Route: `id` UUID PK; `case_id`, `section_id` FKs; nullable `review_decision_id` unique FK, `postapproval_correction_id` unique FK with exactly one nonnull; `kind` `scene_repair|prompt_requalification`; `state` `pending|claimed|uncertain|completed|blocked`; nullable `target_ref` UUID, 004-safe `error_code`; timestamps. The teacher-selected `mixed` category deterministically maps to `prompt_requalification`; no AI classifier or admin override exists. A route is created in the same transaction as its source decision/correction. A budget-exhausted route is retained `blocked/validation` without an invented 011/012 successor.

Outbox: `id` UUID PK; nullable `review_decision_id` unique FK, `postapproval_correction_id` unique FK with exactly one nonnull; `operation` `signal_decision|start_correction`; `workflow_id` varchar(160), nullable `run_id` varchar(160); `state` `pending|sending|uncertain|delivered|blocked`; `attempt_count` unsigned int; nullable `lease_until`, `last_attempt_at`, `delivered_at`, 004-safe `error_code`; timestamps. Decision signal ID is the immutable decision UUID; correction workflow ID is exactly `v3-review-correction-{correction_uuid}`. Insert with the decision/correction transaction before any Temporal call. A dispatcher uses a two-minute DB lease and query/describe reconciliation; it never marks delivered merely because a network request timed out. Only refs/category/outcome reach Temporal, never note text/path/hash, prompt, candidate files or teacher identity.

## `v3_review_preview_sessions`

`id` UUID PK; `case_id`, `section_id`, `review_item_id`, `candidate_id` FKs; `actor_user_id` FK; `worker_session_ref` nullable UUID; `state` `starting|ready|unavailable|closed`; nullable `first_frame_at`, `last_action_at`, `last_action_sha256` char(64), `last_frame_no` unsigned int, `closed_at`, `safe_error_code`; `expires_at` (absolute creation +30 minutes), `idle_expires_at` (last owner action +15 minutes); timestamps. Only one ready/starting session per review item; close the prior session under a review lock before starting another. This DB row contains no scene bytes/frame, and is not approval evidence unless `first_frame_at` is nonnull for the exact item/candidate after an owner-authorized outward GET of frame 0. Bridge start, metadata reads and actions never set this field. Worker process restart or container loss makes it unavailable; it does not change an accepted decision or create a new candidate. Expired sessions are closed and their containers killed; no viewer cookie/capability URL exists.

## `v3_teacher_prompt_corrections` and prerequisite extensions

Effect: `id` UUID PK; `review_route_id` unique FK; `case_id`, `section_id`, `from_prompt_version_id` FKs; `request_sha256`, `template_sha256`, `note_sha256` char(64); captured `template_id` varchar(64), `provider_id` `gemini_api|glm_api|deepseek_api`, `provider_model` varchar(100), `credential_ref` varchar(32); `state` `claimed|uncertain|recorded|blocked`; `send_count` 0 or 1; nullable `result_sha256` char(64), `response_path`, `response_sha256`, `output_path`, `output_sha256`, `returned_model`, `provider_response_id`, `to_prompt_version_id` FK, 004-safe `error_code`, `sent_at`, `recorded_at`; timestamps; unique `from_prompt_version_id`. Claim commits `send_count=1` before the selected provider call. A timeout/5xx after claim is uncertain and cannot be resent automatically; an exact retained known result can reconcile against `result_sha256`. Result validation and private atomic write reuse 010's existing feedback parser and Section/scene-type guard. Under the Section lock, a known valid result inserts one successor and increments 010 `revision_count` once, within captured `prompt_revisions`.

Extend 010 `v3_scene_prompt_versions.origin` with `teacher_correction` and nullable unique `teacher_correction_id` FK; a successor has **exactly one** of `feedback_effect_id` or `teacher_correction_id`, with matching origin/predecessor/Section. Extend 012 `v3_scene_repairs` with nullable unique `teacher_review_route_id` FK and `criteria_schema_version` 1 or 2. V2 criteria are used only for a committed visual teacher route; `RepairCriteriaV2` records exact note bytes privately and still reserves one existing linear `repair_N` slot. Do not add a production placeholder to 010 or 012 while implementing an earlier spec: these extensions are delivered by 013 only.

## Storage, audit and retention

Store notes at `review-notes/{case_id}/{decision_or_correction_id}/{sha256}.txt` on 008 `v3_private`, mode 0600. Stage, fsync, hash, exclusive rename, then commit decision/route/outbox/Section pointer/audit in one DB transaction; rollback leaves an unreferenced file, never a decision without note bytes. An orphan cleaner may remove only unreferenced, nonuncertain files older than 24 hours after DB lookup. Retain all referenced notes, decisions, approvals, routes, outbox entries and uncertain provider effects for pilot and 015 retention. Logs and 004 admin DTO may contain only case/Section refs, fixed stage/state/error/count/timing and actor IDs in restricted audit—not note contents, hashes, paths, scene, prompt or Section values. 004 denial audit applies to every owner route; a failed mutation audit rolls back the decision.
