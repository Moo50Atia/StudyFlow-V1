- Current `routes/web.php` mounts V2 `/sections`, `/lectures`, `/teacher-study-flow` and `/api/lectures`. `TeacherAccessMiddleware` lets admins through and permits student reads; `DynamicViewModel.html_content` is mutable. Use 004's V3 owner policy and 008 `v3_private`; exercise real legacy URLs in tests.
- 012's signed eligibility proof is only an **automated** pass. Recheck the same Laravel current-tip service when making the item, showing context, starting/reusing a preview and submitting a decision. Candidate ID, an old qualification or a successful 011 collection alone is insufficient. The owner is read from the 006 case on every route; a cached teacher ID or `TeacherPermission` row is not authority.
- The review page displays the exact 010 qualified prompt and all eleven 009 Section values as escaped application text. Do not put 011 HTML/JS into Blade, an iframe on the app origin, Livewire/Alpine HTML injection or a public asset URL. The private Python preview gateway runs 011 files only in the 012 restricted container; Laravel returns PNG and bounded escaped control labels. Preview service failure is not a reason to grant approval or spend a repair slot automatically.
- The teacher selects `visual_interaction`, `factual_source` or `mixed`; no classifier or model interprets note category. `mixed` always reopens prompt qualification. A teacher can request changes without first obtaining a frame, but approval requires an owner-authorized outward GET of frame 0 for the exact current item; bridge start alone does not count. Note bytes are private untrusted data and never enter 007 history/admin DTO. CSRF and owner checks apply to every action, frame and decision.
- Visual feedback is a new 013-origin use of 012's **existing** `repair_N` slot/011 request, not a new unlimited correction budget. It keeps the exact current qualified prompt and captured 005 settings/template. Factual/mixed feedback cannot call 010's failed-JEV feedback claim on a passing prompt; add the specified teacher-correction effect and `teacher_correction` version origin, then rerun 010 typed JEV before any 011 scene authoring.
- A case has many 009 Sections. Use one current review/approval pointer **per Section**, one `ReviewGate` instance per Section and historical immutable approvals. `approved_scene_count` is current approved pointers, not number of approval rows. Only all expected current Sections approved yields `complete/approved`.
- Commit decision/route/outbox/audit before Temporal; retry an uncertain signal by exact decision ID after gate query. A later correction to an approved scene uses a separate deterministic CorrectionWorkflow because 007's original closed workflow ID is not reusable. The old approval row stays in history while its current pointer clears. No production 014 recovery or 015 export placeholder belongs in 013.
